# TryRevive 严格信息架构与用户旅程审计

状态：`REVIEW / RESEARCH`，已完成第二轮严格取证，尚未批准实施

审计日期：2026-09-01

外层仓库基线：`codex/organize-project@72e7e42`

候选平台基线：`codex/frontend-platform@763a493`

工作范围：Landing Page、产品入口、产品内信息架构、用户文档、注册/登录/认证、用户旅程连通性

本轮未执行：生产代码修改、DNS 修改、部署、提交、推送、合并

## 1. 严格结论

TryRevive 当前真正的问题不是“核心流程做不通”，而是“核心流程存在于一套候选平台中，但用户没有一个统一、可达、可信的入口进入它”。

严格审计确认：

1. 候选 Vue 平台的学生 P0 闭环真实存在，并通过桌面与移动端浏览器测试；
2. 外层静态产品与候选 Vue 平台是两套不同入口、不同导航和不同身份语义；
3. 两套代码都声明 `tryrevive.online`，但当前自有域名没有可达的产品记录；
4. 仓库中有大量指南和规范，但没有公开、可搜索、可从产品上下文进入的文档中心；
5. 本地使用不需要注册，这是正确的产品边界；缺口只出现在云算力身份不可恢复、无法跨设备管理时；
6. 上一版对“注册硬门槛”“空黑胶页死路”“Privacy 纯孤岛”“旧注意力工具仍在主界面”等判断过重，本版已撤回并修正。

因此，统一方案必须从一条用户生命周期出发，只保留一个产品入口、一个产品状态机、一套导航语义和一套公开事实来源。

## 2. 审计方法与证据等级

### 2.1 四级证据

| 等级 | 含义 | 本文能得出的结论 |
|---|---|---|
| E1 代码存在 | 文件、路由、函数或接口存在 | 只能说明“写了代码” |
| E2 界面可达 | 从用户可见入口可以点击进入 | 可以说明“用户找得到” |
| E3 旅程完成 | 用户能完成目标、产生状态并继续下一步 | 可以说明“本地候选旅程成立” |
| E4 线上验证 | 域名、部署、内容、后端和关键外部服务均独立验证 | 才能说明“当前线上可用” |

静态检查、构建、单元测试、浏览器 E2E 和线上验证不得互相替代。

## 3. 逐项确认：哪些问题真实存在

### 3.1 产品入口割裂：确认存在，严重级别 P0

证据：

- 远端 `master@c6a4734` 保留外层静态产品；
- 远端 `codex/frontend-platform@763a493` 是另一套 Vue/Vite/Electron 候选平台；
- 两套代码的 `CNAME` 都写 `tryrevive.online`；
- 两套界面、数据存储、导航和身份模型不同；
- 没有一份已批准的入口路由表说明哪个是官网、哪个是产品、哪个是历史实现。

这不是“线上有两个按钮”的问题，而是发布治理和用户心智层面的竞争入口：不同分支都可以自称 TryRevive 主产品，却没有唯一 canonical product shell。

### 3.2 当前没有可达的自有域名入口：确认存在，严重级别 P0

2026-09-01 本轮 DNS-over-HTTPS 查询结果：

| 名称 | 结果 |
|---|---|
| `tryrevive.online` A | 权威区存在，但无 A answer |
| `www.tryrevive.online` CNAME | `NXDOMAIN` |
| `app.tryrevive.online` CNAME | `NXDOMAIN` |
| `docs.tryrevive.online` CNAME | `NXDOMAIN` |

所以目前不能说“线上 Landing、App 和文档中心互相割裂”。更准确的事实是：它们都没有形成当前可访问的自有域名用户入口。代码层存在入口竞争，线上层存在入口缺失。

### 3.3 旧静态站存在额外入口步骤：确认存在，但不是注册硬门槛

旧静态站的新访客路径是：

```text
叙事页
  → 本地项目存档页
    → 直接试用 / 建立独立项目存档 / 载入旧存档
      → 项目复活首页
```

确认事实：

- `index.html:121` 的“开始复活一个项目”调用 `skipNarrative()`；
- `app.js:2245` 将用户送到 `login` 视图；
- `index.html:146` 有“直接试用 Try Revive”；
- `app.js:654-687` 创建/恢复 `local_guest` 并直接进入项目流程。

结论：没有“必须注册才能体验”的硬门槛。真实问题是用户点击“开始项目”后并没有马上开始项目，而是先进入一个同时承载游客、创建本地存档和载入存档的身份选择页。它增加一步，并把“设备内存档”包装得像正式账户。

### 3.4 旧注意力工具仍干扰当前主界面：未确认，撤回上一版判断

虽然根目录 HTML 和 JavaScript 仍保留人格测试、主题色、冥想、桌宠和注意力工具代码，但：

- `app.js:2` 设置 `REVIVAL_ONLY_BUILD = true`；
- `style.css:2168-2173` 隐藏注意力工具、云心语和 AI Chat；
- 当前 Guest、Register 和 Login 成功路径都直接进入 `home`，未调用 `startQuiz()`；
- 本轮没有证明人格测试或 onboarding 对新用户可达。

因此它们是代码和维护负债，不应描述为当前可见 IA 的 P0 割裂。只有浏览器实测证明它们可达时，才升级为用户旅程问题。

### 3.5 候选平台核心 P0 旅程割裂：不成立

候选平台状态机包括：

```text
restore → decision → diagnosis → action → execute
→ evidence → return → resume / closed
```

`DecisionSchema` 覆盖 `continue / shrink / help / pause / abandon`。

本轮 E2E 在桌面和移动端都验证了：

- 输入项目材料并生成待确认草稿；
- 确认恢复现场；
- 接受项目判断；
- 获得并确认下一小步；
- 进入专注执行；
- 刷新后保留执行状态；
- 留下文字和文件位置成果；
- 安排下次继续；
- 再次加载后从真实进度继续；
- 已知下一步时跳过推断；
- 暂停/放弃与黑洞历史；
- 本地备份和损坏备份保护。

结果：`24 passed`，耗时 58.9 秒。这个证据证明 `763a493` 的预构建候选 Web 在受控本地环境中具备完整 P0 闭环，不证明已部署，也不证明真实学生接受。

### 3.6 黑胶星球是孤立死路：不成立，但顶层权重需要调整

确认事实：

- 空收藏页明确解释“先完成或明确放下一个真实项目”；
- 页面有“回到项目工作台”主动作；
- 有项目时可以选择、播放、收藏和导出；
- E2E 验证路由返回、刷新和跨项目选择。

因此它不是死路。问题在于它作为主导航第二项，对第一次恢复项目的用户权重过高。它应该在用户完成/放下至少一个项目后成为主要入口，之前只作为成果历史的次级入口。

### 3.7 About 是弱连接信息页：确认存在，严重级别 P1

`AboutView.vue` 只有“返回工作台”。它能解释价值，但不能：

- 带示例开始第一次复活；
- 进入 3 分钟教程；
- 返回用户打开 About 前的具体项目和阶段。

它不是绝对死路，但只有通用返回，没有基于阅读意图的下一动作。

### 3.8 Privacy 是纯孤立页：不成立，但上下文回流不完整

确认事实：

- Privacy 有 OpenAI 数据说明外链；
- 桌面端已认证时可以执行云数据导出、原文检查和账户删除；
- 页面可返回工作台或进入 About；
- Web 端会明确说明云功能仅桌面内测，并禁用不可用按钮；
- E2E 在桌面与移动 Web 均验证了该边界。

真实缺口：从某个上传、支付或账户动作跳入 Privacy 后，页面不会记住并返回原任务；本地备份控制也不在这里，用户需要自己理解“本地数据”和“云数据”是两套入口。

### 3.9 404 静默回根：确认存在，严重级别 P1

候选路由把所有未知路径直接重定向 `/`。用户无法知道链接已失效，也无法选择：

- 返回上一个项目阶段；
- 搜索帮助；
- 打开最近项目；
- 报告坏链接。

这会掩盖文档深链、活动链接或通知链接的失效问题。

### 3.10 文档中心缺失：确认存在，严重级别 P0

仓库目前有 24 份 Markdown 文档，覆盖产品、体验、研究、增长、决策、部署、功能、Marketing 和协作，但：

- `docs/README.md` 只是仓库目录；
- 没有面向用户的文档站构建、路由、搜索和公开白名单；
- 没有左侧章节树、右侧本页目录和产品上下文返回；
- 没有统一 owner、last reviewed、适用版本和公开级别元数据；
- 多份文件仍描述旧版本状态；
- `README.md` 仍保留一个“外发前需复核”的 GitHub Pages 地址；
- 内部 PRD、研究、部署和 AI 协作文档不适合原样公开。

相对 Markdown 文件链接本轮未发现断链；这只证明仓库内文件引用基本连通，不证明用户文档旅程成立。

### 3.11 注册、登录和认证缺口：对本地核心不成立，对云身份成立

#### 本地核心

学生 MVP 明确要求首次无需注册。候选平台本地流程符合该要求，E2E 也验证本地备份无需账户。因此“缺少注册页”不是 P0 产品缺陷，不能为了形式完整强行增加登录墙。

#### 旧静态站本地身份

旧静态站的用户名和密码只隔离同一浏览器的 `localStorage` 存档。它不是跨设备账户、不是云认证，也没有密码找回。文案必须叫“本地存档”，不能叫正式账户登录。

#### 候选平台云身份

候选桌面平台使用兑换码创建匿名云账户和 Bearer session：

- session token 用 Electron `safeStorage` 加密保存；
- 退出时远端 revoke 并清除本机 token；
- Worker 有账户状态、会话撤销、云导出、源内容删除和账户删除接口；
- Web 端不保存云凭据，并明确云功能只在桌面内测。

确认缺口：没有邮箱/Passkey 登录、找回流程、设备列表、跨设备恢复或把匿名余额绑定到可恢复身份的旅程。只要云功能仍是封闭兑换码内测，这可以是已知限制；一旦允许正式购买或承诺跨设备，它就是 P0 阻断项。

## 5. 统一信息架构的核心原则

### 5.1 先定义用户旅程，再定义页面

页面不能因为“已有组件”就进入导航。每个页面必须服务以下旅程状态之一：

```text
理解价值
→ 带项目开始
→ 恢复现场
→ 做项目判断
→ 确认下一步
→ 执行
→ 留下进度
→ 安排回流
→ 从上次继续
```

账户、隐私、文档、收藏和设置都是支撑层，不能成为与主旅程并列的另一套产品。

### 5.2 一个产品只有一个公开入口

唯一公开入口为：

```text
https://tryrevive.online/
```

所有搜索、社交内容、活动二维码、README 和外发材料都指向它。不得同时把 GitHub Pages、旧静态站、候选预览和桌面下载页称为“TryRevive 官网”。

允许通知或本地书签直达具体项目，但它们属于“继续旅程”的深链，不是第二个产品入口。

### 5.3 技术子域不等于用户入口割裂

文档中心可以使用 `docs.tryrevive.online` 独立部署，为后续反向代理做准备，但必须满足：

- 全站使用同一品牌、术语和顶部全局导航；
- 产品内帮助直接进入对应文档，不进入文档首页重新找；
- 文档保留“返回项目 / 返回刚才步骤”；
- 文档 CTA 返回同一个 canonical product journey；
- 文档不提供另一套注册、账户或项目首页。

用户看到的是一个产品体系，技术上才是两个构建产物。

### 5.4 登录不等于同步，文档不等于产品

- 登录只确认身份；
- 同步必须是独立、可撤回的授权；
- 文档解释和解决问题，但最终要返回用户的真实项目动作；
- 收藏展示结果，但不替代工作台；
- Landing 负责决定“要不要开始”，不承担项目编辑。

## 6. 统一后的完整用户旅程

### 6.1 新用户主旅程

```text
外部来源
→ Landing 首屏
→ 复活我的项目
→ 匿名本地项目 Intake
→ 恢复现场
→ 继续 / 缩小 / 求助 / 暂停 / 放弃
→ 下一小步
→ 执行
→ 留下进度
→ 安排回流
→ 完成首次价值
```

入口规则：

- Landing 只有一个高强调主 CTA；
- CTA 直接进入项目 Intake，不再经过“登录/注册/游客三选一”；
- “已有本地项目”作为次级入口，自动进入最近项目；
- 注册只能在用户需要跨设备、购买或云恢复时出现。

### 6.2 回访用户旅程

```text
打开 tryrevive.online
→ 检测到本地项目
→ 从「项目名」上次进度继续
→ 展示上次成果 + 下次入口
→ 继续当前动作
```

回访用户的主 CTA 必须从“复活我的项目”变为“从上次进度继续”。新建项目降为次级动作。

### 6.3 帮助旅程

```text
用户在某一具体步骤遇到问题
→ 点击当前步骤的“帮助”
→ 打开 docs 对应文章与锚点
→ 解决问题
→ 返回同一项目、同一阶段、同一草稿
```

帮助链接至少携带非敏感上下文：平台、页面、阶段、错误码和 `return_to`。不得携带项目正文、token、邀请链接或私人材料。

### 6.4 数据与账户旅程

```text
设置
→ 数据与账户
  ├─ 本地项目：导出 / 导入 / 清除本机
  ├─ 云端算力：余额 / 订单 / 退出本设备
  ├─ 云端内容：导出 / 检查原文 / 删除
  └─ 可恢复身份：登录 / 找回 / 设备管理（未来）
```

四者必须分区展示，不能再让“本地存档”“云算力账户”和“项目同步”共用模糊的“账户”一词。

### 6.5 完成与收藏旅程

```text
完成或明确放下项目
→ 留下最终状态
→ 可选进入收藏/黑洞历史
→ 查看、播放或导出
→ 返回工作台 / 开始下一项目
```

黑胶星球不是主链入口，而是主链完成后的成果空间。没有收藏时只展示一个动作：回工作台完成或放下真实项目。

## 7. 统一产品信息架构

### 7.1 一级结构

```text
TryRevive
├─ 首页 / Landing
├─ 项目
│  ├─ 最近项目 / 从上次继续
│  ├─ 新建项目
│  ├─ 当前项目流程
│  └─ 项目列表：进行中 / 已暂停 / 已完成 / 已放下
├─ 成果
│  └─ 黑胶星球与黑洞历史
├─ 帮助
│  └─ docs.tryrevive.online 对应上下文
└─ 设置
   ├─ 本地数据
   ├─ 云端算力与账户
   ├─ 隐私与权限
   └─ 关于与版本
```

### 7.2 Landing Page 信息架构

顺序必须跟随用户是否愿意开始的决策：

1. **主承诺**：把停住的项目，接着做下去；
2. **唯一主动作**：复活我的项目 / 从上次进度继续；
3. **适合谁**：课程、竞赛、作品集、科研和毕业设计；
4. **会得到什么**：找回现场、今天一步、下次入口；
5. **三步工作方式**：恢复 → 行动 → 留下进度；
6. **真实界面示例**：明确标为模拟项目，不伪装用户案例；
7. **项目判断分支**：继续、缩小、求助、暂停、放弃；
8. **信任边界**：首次无需注册、默认本地、不自动改文件；
9. **关键 FAQ**：只回答影响开始决策的问题，深链文档；
10. **末屏同一 CTA**；
11. **Footer**：指南、隐私、版本、状态、反馈。

Landing 不再承载本地存档创建、项目编辑、黑胶操作或长篇隐私控制。

### 7.3 产品内全局导航

#### 新用户、无项目

```text
TryRevive | 项目 | 帮助 | 设置
```

隐藏“成果”的一级入口，避免空收藏抢占注意力。

#### 已有项目

```text
TryRevive | 当前项目 | 所有项目 | 成果 | 帮助 | 设置
```

当前项目页面继续保持“一页一个主要动作”；全局导航视觉降权，执行模式可暂时隐藏。

#### 移动端

- 主要旅程动作留在页面底部安全区；
- 全局导航进入精简菜单；
- 不把项目阶段导航和全局站点导航混成同一排标签；
- 帮助打开后必须能一键返回原步骤。

### 7.4 路由模型

建议由唯一产品实现承载以下语义路由：

```text
/
/start
/projects
/projects/:projectId
/projects/:projectId/restore
/projects/:projectId/decision
/projects/:projectId/action
/projects/:projectId/execute
/projects/:projectId/evidence
/projects/:projectId/return
/collection
/settings/data
/settings/account
/privacy
/about
/not-found
```

状态机仍是事实源；路由只是可恢复、可分享但不泄露内容的用户入口。直接访问不匹配当前状态的阶段时，应解释并恢复到项目真实阶段，不静默重置或跳首页。

## 8. 文档中心方案

### 8.1 文档中心在用户旅程中的职责

文档中心不是仓库 `docs/` 的网页皮肤，而是产品的“解决问题层”：

- 新手通过教程完成第一次成功；
- 正在工作的人通过 How-to 解决具体任务；
- 遇到错误的人通过故障排查回到原步骤；
- 需要信任依据的人查看数据和隐私参考；
- 团队内部 PRD、研究、部署和 AI 协作不进入公开站。

### 8.2 域名与反向代理准备

首期技术源站：

```text
docs.tryrevive.online
```

未来如需统一到 `tryrevive.online/help/*`，由反向代理映射到独立文档源站。必须预留：

- 可配置 base URL 和静态资源前缀；
- canonical 与 301/308 重定向表；
- 相对内部链接；
- 独立缓存和回退；
- host-only Cookie；
- 不共享产品认证 token；
- `return_to` 白名单；
- 搜索索引只包含公开白名单。

### 8.3 左侧边栏：按用户任务组织

```text
开始使用
  TryRevive 是什么
  3 分钟复活第一个项目
  完成一步并留下进度
  下次从哪里继续

推进项目
  找回上次现场
  继续、缩小或求助
  换一步或自己修改
  暂停、放弃与重新开始
  记录文字、链接和文件成果

账户与数据
  无注册本地使用
  本地数据、云算力与同步的区别
  导出与恢复本地备份
  登录、退出与找回（开放后）
  导出或删除云端数据

故障排查
  项目没有保存
  备份无法导入
  链接或材料无法读取
  会话失效或兑换码失败
  支付后余额未更新
  云端分析失败

功能与边界
  网页版与桌面版能力
  支持的材料和限制
  隐私与数据保留
  当前版本与已知问题

理解 TryRevive
  为什么第一次无需注册
  为什么一次只有一步
  什么算实质推进
  为什么暂停或放弃也可能正确
```

### 8.4 右侧目录

- 只显示当前页 H2 和必要 H3；
- 少于 3 个 H2 时隐藏；
- 当前章节随滚动高亮；
- 移动端折叠为“本页内容”；
- 页面底部固定提供“返回刚才步骤”、上一篇/下一篇和反馈；
- 操作指南页额外显示前置条件、预计时间和完成结果。

### 8.5 搜索与深链

- 中文搜索覆盖标题、正文、同义词、错误码和平台；
- 搜索结果显示适用版本、Web/Desktop 和最近审核日期；
- 产品错误提示直接链接到对应文章锚点，而不是文档首页；
- 零结果提供相关排障和反馈；
- 不把搜索词与项目正文绑定，不采集 token 或私密材料。

### 8.6 公开内容治理

公开页面必须具备：

```yaml
title:
description:
audience:
content_type: tutorial | how-to | reference | explanation
product_status: current | partial | planned
applies_to: web | desktop | both
owner:
last_reviewed:
source_of_truth:
public: true
```

公开构建采用白名单。默认禁止公开：

- `AGENTS.md` 和 `docs/collaboration/`；
- 内部部署路径与控制面细节；
- 未脱敏研究记录；
- 内部增长实验；
- 未批准 PRD、ADR 和未来能力；
- 密钥、token、真实用户数据和私有报名材料。

## 9. 认证与账户完整方案

### 9.1 P0：继续无注册本地核心

- 第一次体验不出现注册墙；
- 本地项目自动保存；
- 用户可主动导出与恢复；
- 本地数据损坏、导入失败和清除都有明确恢复路径；
- 文案统一使用“本地项目”或“本地存档”。

### 9.2 内测云算力：准确命名

在没有可恢复身份前，统一叫：

```text
本设备的云端算力会话
```

不得笼统叫“登录账户”。兑换前、退出前和购买前必须说明：

- 凭据保存在本设备；
- 退出会撤销本设备 session；
- 本地项目不会因为连接云算力而自动同步；
- 当前是否支持找回和设备迁移。

### 9.3 正式收费或跨设备前的认证门

必须实现并验收：

```text
匿名本地使用
→ 需要购买 / 跨设备 / 云恢复
→ 创建可恢复身份（邮箱 magic link 或 Passkey，待选型）
→ 绑定现有匿名算力余额
→ 显示设备与会话
→ 用户单独选择是否同步项目
```

必备旅程：登录成功/失败、链接过期、离线、限流、新设备、找回、退出当前设备、退出所有设备、删除账户、导出数据、支付成功/取消/待确认和余额迁移。

### 9.4 同步是独立产品决策

即使用户登录，也默认只绑定身份和权益。项目正文、成果和附件只有在单独同意后才能同步。必须先定义：

- 同步范围；
- 冲突解决；
- 离线编辑；
- 加密与保留期；
- 撤回与删除；
- 本地数据迁移；
- 多设备重复项目处理。

## 10. 实施顺序

### Phase 0：锁定唯一事实源与主线

1. 产品负责人批准候选 Vue 平台是否为唯一产品主线；
2. 旧静态运行时冻结为历史参考，不再作为第二入口继续演进；
3. 更新 `PROJECT_STATE`、版本地图和事实清单；
4. 建立唯一入口路由表、术语表和能力状态表。

退出条件：团队能唯一回答“官网是什么、产品是什么、当前线上是什么、哪些只是候选”。

### Phase 1：统一入口与产品 Shell

1. 在唯一实现中加入 Landing；
2. Landing CTA 直接进入匿名项目 Intake；
3. 为回访者提供“从上次进度继续”；
4. 统一项目、成果、帮助、设置；
5. 增加显式 404 和状态恢复；
6. About、Privacy、帮助保留原任务返回上下文。

退出条件：新用户和回访者都不需要在两套产品或身份页之间做选择。

### Phase 2：文档中心 MVP

1. 以 8–12 篇 P0 用户文档验证 Docusaurus 与 VitePress；
2. 建立公开白名单；
3. 实现左栏、右侧目录、中文搜索和移动导航；
4. 每篇文档返回具体产品步骤；
5. 先部署预览，不改 DNS。

退出条件：五个高频问题能在一次搜索或两次点击内解决，并回到原项目阶段。

### Phase 3：发布入口

1. 在批准的预览 SHA 上做桌面/移动人工验收；
2. 分别验证远端 commit、构建、预览 URL、DNS、TLS、canonical、404 和缓存；
3. 获得明确授权后再配置自有域名；
4. 外发材料只保留唯一入口。

退出条件：入口、部署和线上内容三者指向同一批准版本。

### Phase 4：可恢复云身份

只在正式收费或跨设备需求成立时启动。先完成身份与权益恢复，再决定项目同步。

## 11. 禁止再次出现的割裂规则

以下规则应成为产品验收硬门：

1. 不允许两个 URL 同时自称产品首页；
2. 不允许两个运行时同时作为 CURRENT 主产品；
3. 不允许 CTA 把用户带到与承诺无关的身份或设置页；
4. 不允许帮助文章结束后丢失原项目和原阶段；
5. 不允许登录自动等于项目同步；
6. 不允许错误路由静默重置到首页；
7. 不允许信息页只有浏览器后退这一条出路；
8. 不允许未完成/未上线能力进入公开导航；
9. 不允许内部文档混入用户文档搜索；
10. 不允许 GitHub Pages、预览 URL、子域和生产域名混称“已上线”。

## 12. 验收标准

### 12.1 入口

- 所有公开来源进入同一 Landing；
- Landing、App、Docs 使用相同品牌、术语和状态说明；
- 新用户一个 CTA 进入匿名 Intake；
- 回访用户一个 CTA 进入最近项目；
- 直接深链失效时有解释和恢复路径。

### 12.2 主旅程

- 桌面和移动均完成恢复、判断、动作、执行、成果、回流和再次进入；
- 刷新、后退、关闭重开不丢状态；
- 暂停、放弃、导入失败和材料失败都有下一动作；
- 每页保持一个主要动作。

### 12.3 帮助与信息

- 产品内帮助直达对应文章和锚点；
- 文档可返回原项目、原阶段；
- About 有“开始项目 / 3 分钟教程 / 返回原处”；
- Privacy 统一解释本地数据、云数据、云算力和账户；
- 404 不再静默回根。

### 12.4 账户

- 本地核心无需注册；
- 云算力会话不冒充可恢复账户；
- 正式收费前具备找回、会话管理和余额迁移；
- 登录与同步分别同意、分别撤回。

## 13. 外部最佳实践依据

- [Diátaxis：教程、How-to、参考和解释](https://diataxis.fr/start-here/)：用于让文档对应不同用户任务，不把仓库文件夹直接变成用户导航。
- [Docusaurus Sidebar 官方文档](https://docusaurus.io/docs/sidebar)：用于左侧章节树、有序分组和前后翻页。
- [Cloudflare 子域管理](https://developers.cloudflare.com/fundamentals/manage-domains/manage-subdomains/)：用于区分子域、DNS 记录、代理和证书，不把代码中的 `CNAME` 当成线上已配置证据。

这些资料是设计依据，不代表技术选型、代理、DNS 或部署已经完成。

## 14. 推荐的单一下一步

产品负责人先确认：`codex/frontend-platform@763a493` 是否作为后续唯一产品主线，旧静态运行时是否冻结为历史实现。

只有这个决定确认后，才应为唯一主线设计统一 Landing、产品 Shell、帮助深链和文档中心预览；否则继续优化页面只会把两套入口都做得更完整，也让割裂更难回退。
