# ADR-003：唯一产品主线、公开入口与信息架构

状态：已接受，待分阶段实施与独立审计

决定日期：2026-09-01

决定人：产品负责人

实施负责人：Codex

## 背景

严格审计确认，TryRevive 同一仓库中存在根目录静态产品与 Vue/Vite/Electron 候选平台两套运行时。两者共享品牌与 `CNAME` 语义，但导航、数据、身份和用户旅程不同。候选平台 `codex/frontend-platform@763a493` 已在桌面及移动 Web E2E 中完成学生 P0 闭环；根静态产品仍包含历史入口和本地存档模型。

产品不能继续让两套运行时同时成为 CURRENT 主入口。

## 决定

1. `codex/frontend-platform@763a493` 作为统一信息架构的实现基线与后续唯一产品主线。
2. 根目录静态运行时冻结为历史实现；未经新的产品决定，不再扩展其 Landing、账户、导航或外围功能。
3. `https://tryrevive.online/` 是唯一公开产品入口。搜索、活动、README、社交内容和二维码最终都指向该入口。
4. 产品只保留一条主旅程：理解价值 → 带项目开始 → 恢复现场 → 项目判断 → 下一小步 → 执行 → 留下进度 → 回流 → 从上次继续。
5. `docs.tryrevive.online` 是独立部署的帮助系统，不是第二个产品入口。文档必须支持从产品具体步骤进入并返回原项目、原阶段。
6. 本地核心继续无需注册。云端身份、算力权益和项目同步是三个独立概念；登录不得自动等于同步。
7. 未知路由不得静默重定向首页；必须提供解释、最近项目和帮助入口。

## 用户可见一级结构

```text
首页 / Landing
项目
成果
帮助
设置
```

“成果”根据用户生命周期动态显示：无完成或放下记录时降为次级入口；产生真实结果后进入一级导航。

## 技术边界

- 主产品继续复用候选平台现有状态机与本地持久化，不重新实现核心闭环。
- Landing 与产品工作台属于同一 canonical 产品实现。
- 文档中心使用公开内容白名单，禁止原样发布内部 `docs/`。
- 子域、反向代理、DNS、部署、提交和推送分别经过独立授权与验证。

## 被否决的方案

### 同时维护两个公开产品入口

否决原因：用户无法判断哪个是当前版本，数据与账户语义无法一致，测试和发布成本翻倍。

### 先增加强制注册再统一旅程

否决原因：违反首次无需注册的学生 MVP 不变量，并把身份成本放在首次价值之前。

### 把仓库 `docs/` 原样生成公开站

否决原因：内部 PRD、研究、部署和协作资料与学生任务不同，也存在公开范围和状态漂移风险。

## 后果

- 后续实现必须在隔离任务分支/工作树进行，避免叠加当前未归属的数据库和 Worker 改动。
- 旧静态运行时继续保留以便比对和回退，但不再决定产品 IA。
- 所有新增页面必须说明服务的用户旅程状态、主动作、产生的状态和下一步。
- 每个实施阶段完成后立即启动独立只读审计；审计与下一阶段并行，问题进入修复队列。
