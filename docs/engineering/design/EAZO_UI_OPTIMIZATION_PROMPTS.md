# Eazo Creator UI 优化提示词包

状态：可直接复制使用；先做私有原型，不授权部署

更新日期：2026-08-02

## 1. 先确认产品与会员边界

这里指 [Eazo Creator](https://eazo.ai/creator/)，不是 Eazo Agent Kit 或其他产品。公开页面说明 Creator 可以生成前端、后端、数据库和部署，并提供 Design style 与 Live app；但公开资料没有足够信息确认你的会员额度、刷新日期、私有项目数、版本历史或代码导出权益。

开始前先在 Billing / Plan 页面记录：

- 剩余生成或积分额度；
- 刷新日期；
- Private / Unlisted / Restricted；
- Remix 开关；
- Version history / Branch / Duplicate；
- Export code；
- 是否能恢复到旧版本。

若要精确分配会员额度，需要保存这些页面的截图。本提示词不会猜测套餐权益。

## 2. 隐私设置先于上传

Eazo 的隐私政策说明，Creator 可以处理提示词、文件、图片、代码和配置；如果发布前没有选择可用的私有、非公开或受限可见性，作品可能默认公开，公开作品还可能允许 Remix。参考 [Eazo Privacy Policy](https://eazo.ai/privacy-policy)。

上传前：

1. 如果账户明确提供，将项目设为 Private 或 Restricted，并确认实际可见范围；
2. 明确关闭 Remix；
3. 删除 `.env`、Secret、Token、API Key、真实用户数据和未授权项目材料；
4. 不上传完整浏览器存储或生产日志；
5. 先创建副本或版本，不覆盖当前项目；
6. 在得到人工确认前不部署、不公开、不分享链接。

`Unlisted` 不等于私有，只适合已经可以公开、但不主动展示的内容。如果界面无法明确确认 Private/Restricted 和 Remix 状态，不上传源码、PRD 或未公开资料，只使用脱敏截图和简化文字。

## 3. 当前 UI 诊断

基于当前桌面端和手机端完整流程截图，首轮应优先解决：

- 深色、技术化、英语和中文混用，学生第一眼难以判断产品用途；
- `ONE QUIET CONVERSATION`、`REVIVAL BRIEF`、`REAL PROGRESS RECORDED` 等内部术语暴露；
- 完成页仍保留大面积 Hero，真正成果被推到首屏以下；
- 完成卡片包含过多徽章、面板和信任说明，主结果不突出；
- 手机端顶部导航过小，主结果和主要按钮落在折叠线以下；
- 没有明确出现课程、竞赛、作品集或毕业设计；
- 叙事、本地存档、登录、人格、主题、注意力、冥想、桌宠和 Dock 容易阻挡首次价值。

本轮不是换一套皮肤，而是让核心价值在三分钟内出现。

## 5. 最大化会员价值的顺序

不要用一个巨型提示词要求 Eazo 同时审计、重画、写代码和部署。每轮只完成一种高价值产出，并在满意后保存版本：

1. UX 审计，不改代码；
2. 新信息架构与低保真流程；
3. 三条独立视觉分支；
4. 选择一个方向；
5. 补全空、错、加载、暂停、放弃和回流状态；
6. 用 Grill 评审找 P0/P1 问题；
7. 只修 P0/P1；
8. 做响应式和可访问性检查；
9. 最后一轮才适配现有原生代码；
10. 核心产品稳定后，再单独制作增长落地页和社交分享素材。

## 6. 第一轮提示词：只做信息架构

```text
你是资深消费级 AI 产品设计负责人。请基于我上传的脱敏截图、目标用户和体验规格，重新设计 TryRevive 的核心信息架构。

本轮只做用户流程、页面主动作、中文文案和状态清单。不要做视觉风格，不要生成高保真，不要生成或修改代码，不要启用数据库、云存储、分析、认证、外部 API 或部署。

这是概念原型。下面的“项目判断”“需要帮助”“放弃”和条件式追问不一定被当前生产代码支持；请把它们标记为 NEW CONCEPT，不要假装已经实现。生产适配要在后续单独输出字段、路由和现有状态映射。

【产品定位】
TryRevive 是面向在校大学生的“停滞项目复活工具”。

首发用户拥有一个已经停滞至少 7 天的课程项目、竞赛项目、作品集、科研或毕业设计，并且未来 90 天存在提交、答辩、展示、比赛或申请节点。

用户最痛的时刻是：
“我知道这个项目必须继续，但已经忘了上次做到哪里，也不知道现在做哪一步最有用。”

产品价值不是生成更长的计划，而是：
1. 找回上次做到哪里；
2. 判断项目应该继续、缩小、求助、暂停还是放弃；
3. 给出一个今天能完成、有完成标准的小步骤；
4. 完成后留下真实进度；
5. 下次不用重新理解项目。

【成功标准】
- 首次用户无需注册，在 3 分钟内得到一个自己认可的下一小步；
- 每个页面只保留一个主要动作；
- 移动端单手即可完成核心流程；
- 降低重新进入项目的心理负担，但不使用心理治疗、诊断或自律羞辱语言。

【核心流程】
1. 欢迎页
   - 标题：让搁置的大学项目重新动起来
   - 副标题：找回上次做到哪里，完成今天最关键的一步；下次从真实进度继续。
   - 主按钮：复活我的项目
   - 辅助信息：无需注册即可试用 · 数据默认保存在本机
   - 展示四个简短场景：课程大作业、竞赛 Demo、作品集、毕业设计
   - 不播放强制叙事动画

2. 恢复现场
   每次只问一个问题，总计不超过 5 个核心问题：
   - 这是什么项目？
   - 最近一次实际完成了什么？
   - 最接近的截止节点是什么？
   - 当前最大的阻力是什么？
   - 今天能投入多少时间？
   显示明确进度、允许返回修改、允许稍后补充。
   不要求先登录、做人格测试或选择主题色。

3. 项目判断
   给出五个平等选项：继续、缩小目标、需要帮助、暂停、放弃。
   不默认所有项目都必须复活。

4. 可选追问实验
   提供次要按钮“帮我问清楚”。
   只在用户主动选择、信息不足或建议被拒绝时出现，最多追问 3 个高价值问题。
   用户可以随时跳过或选择“直接给我一个下一步”。
   不在用户界面出现 RSI、Loop、GrillMe、Agent 等内部词汇。

5. 下一小步
   页面只突出一张行动卡：
   - 现在做什么
   - 预计 5–20 分钟
   - 什么状态算完成
   - 为什么建议这一步
   按钮：现在开始、再缩小一点、换一个、自己修改、先暂停。

6. 执行页
   只显示当前动作、完成标准、计时器和工作入口。
   允许暂停、完成、反馈“还是太大”。
   不加入桌宠、禅修、MBTI、励志警告或无关推荐。

7. 留下进度
   使用“留下进度”，不要使用 Completion Evidence。
   支持文字、链接或文件名。
   解释：这是为了让下次不用重新回忆，不是为了审查用户。
   用中性问题询问：和开始之前相比，这份成果是否让项目产生了实质推进？选项为“是 / 否 / 不确定”，不要用庆祝文案诱导答案。

8. 完成与回流
   清楚展示：
   - 这次实际完成了什么
   - 下次从哪里继续
   - 下次继续时间
   主按钮：保存并结束
   次按钮：生成下一小步
   不使用夸张庆祝动画。

【必须避免】
- 不展示虚构用户证言、用户数量、成功率或“已有 1000 名学生”等未经验证的数据；
- 不把“三个月 1000 名用户”作为用户可见文案；
- 不声称会自动修改文件、提交代码或发送消息；
- 不加入医疗、心理治疗或注意力障碍诊断表达；
- 不为了视觉效果增加首轮步骤；
- 不改变现有核心功能。

【本轮输出】
1. 新旧信息架构对比；
2. 首次用户流程；
3. 页面清单和每页唯一主动作；
4. 关键中文文案；
5. 空、错、加载、暂停、放弃等状态；
6. CURRENT 与 NEW CONCEPT 对照表；
7. 新概念到现有 brief / running / evidence / completed / paused 的待确认映射；
8. 仍需由我决定的问题。

完成后停止，等我确认。不要继续做视觉或代码。
```

## 7. 第二轮提示词：只做视觉原型

在确认第一轮输出后再使用：

```text
使用我已经确认的信息架构、中文文案和页面主动作，只制作视觉概念原型。不要改流程、不要新增功能、不要生成生产代码。

原型只使用模拟或内存数据。不要启用 Eazo 数据库、云存储、分析、认证、外部 API、MCP、发布或部署。所有 NEW CONCEPT 继续保留标记，不得声称当前产品已经实现。

本轮只生成四张相同关键页面：
1. 欢迎；
2. 恢复现场；
3. 下一小步；
4. 完成与回流。

【视觉方向】
使用 Warm Minimalist 作为视觉参考关键词；如果账户中存在同名可选风格，可以使用该预设，否则只按以下特征设计：
- 浅色优先，背景为柔和米白或冷白；
- 正文使用深灰黑；
- 主色使用克制的鼠尾草绿或暖珊瑚色；
- 清晰、安静、有行动感，但不是冥想或心理治疗产品；
- 适合大学生，但不要幼稚、卡通化或多巴胺 UI；
- 使用 8px 间距系统；
- 卡片圆角 12–16px，阴影轻微；
- 中文正文优先使用系统无衬线字体；
- 不使用大面积渐变、霓虹、重玻璃拟态、3D 装饰、漂浮球或无意义动画；
- 不混用大量英文 eyebrow 标签。

【响应式与可访问性】
先生成 390×844 手机端四页，再展示同一四页的 1440×900 桌面适配。
按钮触控区域至少 44×44px；文字和控件达到 WCAG AA 对比度；提供清晰键盘焦点；不只依靠颜色表达状态；支持 prefers-reduced-motion；考虑软键盘、200% 缩放和长中文。

【本轮输出】
1. 四页视觉稿；
2. 设计 tokens；
3. 组件清单；
4. 移动端与桌面端差异；
5. 所有 NEW CONCEPT 标记。

完成后停止。不要扩展完整流程，不要写代码，不要部署或公开。
```

## 8. 三条独立视觉分支

页面结构、文案和交互完全相同，只改变视觉系统。每种风格只生成欢迎、恢复现场、下一小步、完成回流四张关键页；选定一个方向后才扩展完整流程，避免把额度花在三个完整应用上。以下名称是当前展厅中的视觉参考关键词，不保证你的账户中存在稳定同名预设。

### A：Warm Minimalist

使用第二轮提示词中的视觉方向，作为基线。

### B：Swiss Grid Logic

```text
保持已确认的四张关键页面、中文文案、组件和交互完全不变。不要新增功能。以 Swiss Grid Logic 为视觉参考关键词：使用更强的网格、排版层级和信息清晰度，白底、深墨色、单一蓝绿色强调色。适合严肃但不沉重的大学生生产力工具，避免企业后台感、密集数据表和开发者控制台感。只输出四张关键页，不生成完整应用或代码。
```

### C：Classic Notebook

```text
保持已确认的四张关键页面、中文文案、组件和交互完全不变。不要新增功能。以 Classic Notebook 为视觉参考关键词：使用非常克制的纸张和项目笔记意象，让“找回现场”和“从上次继续”更直观。纸张纹理只能作为低对比背景，不能降低可读性；不要做成手账、儿童插画、复古装饰页或学习打卡 App。只输出四张关键页，不生成完整应用或代码。
```

评分表：

- 三秒内是否知道产品做什么；
- 点击 CTA 后多久看到实际价值；
- 是否必须先注册或做无关选择；
- 下一小步是否是视觉唯一焦点；
- 学生是否理解“留下进度”；
- 手机端是否可单手完成；
- 是否仍像冥想、人格测试或自律工具；
- 是否引入了当前产品没有的承诺。

选定一个方向后再要求：`只沿选定方向扩展完整流程和空、错、暂停、放弃状态；不要混入另外两种风格。`

## 9. Grill UI 评审提示词

在选定一个版本后先做评审，不要继续美化：

```text
现在不要修改界面。进入 Grill 评审模式。

你是一名第一次打开 TryRevive 的中国在校大学生，今晚还有课程大作业，但这个项目已经停了两周。你只有 3 分钟耐心，使用 390×844 的手机，没有读过产品介绍，也不理解 Revival、Evidence、Agent、Loop 等术语。

请以挑剔、具体、可验证的方式审查当前原型，不要礼貌性表扬。

输出：
1. 一句话毒舌结论；
2. 最可能导致退出的前 10 个点，按 P0/P1/P2 排序；
3. 每个问题对应的具体页面、控件或文案；
4. 用户此刻会怎样理解，以及为什么可能理解错；
5. 最小修改方案，不允许借机增加新功能；
6. 首次价值出现前的点击数、输入数和非必要步骤数；
7. 模拟课程项目、竞赛 Demo、作品集、毕业设计四种流程；
8. 找出心理治疗感、羞辱感、企业软件感、AI 套壳感或虚假承诺；
9. 检查移动端、键盘操作、对比度、长中文、空状态和错误状态；
10. 给出“继续迭代 / 回到线框 / 暂停上线”三选一结论和证据。

不要生成代码，不要重画页面，先只完成评审。
```

修复提示词：

```text
只修复上一轮 Grill 报告中的 P0 和 P1。不要处理 P2，不要新增页面，不要改变产品定位，不要重新选择视觉风格。逐项列出修改前、修改后和预期影响，再更新原型。
```

## 10. 最后一轮代码交付提示词

```text
把已经确认的原型适配回当前 TryRevive 工程。

技术约束：
- 当前项目使用原生 HTML、CSS、JavaScript；
- 不迁移到 React、Vue 或其他框架；
- 不安装新依赖；
- 先输出 CURRENT 与 NEW CONCEPT 的字段、路由和状态映射；“需要帮助”“放弃”和条件式追问若没有现有实现，只保留在独立原型，未经确认不得接入生产代码；
- 保留现有 brief / running / evidence / completed / paused 状态；新增体验优先映射到现有状态，不擅自扩展 schema；
- 保留所有被 JavaScript 查询的 DOM ID、表单 name/value 与枚举值、全局 handler 名、内联事件入口、核心函数、localStorage schema 和状态迁移；
- 不修改项目复活、计时、进度记录和回流逻辑；
- 只重构表现层、布局、组件样式和用户可见文案；
- 先建立并行 prototype，不覆盖原文件；
- 输出设计 token 与现有 CSS 变量的映射；
- 输出旧 DOM selector 到新组件的逐项映射；
- 列出每个拟修改文件和原因；
- 标出所有可能破坏现有功能的改动；
- 先输出逐文件 diff/patch，不交付整文件覆盖版；由人工应用后再运行现有测试；
- 在得到确认前不要部署、发布或公开项目。

完成后逐项验证：
390×844、360×800、768×1024、1440×900；
键盘操作；
200% 缩放；
prefers-reduced-motion；
空、错、暂停、放弃和长文本；
现有复活闭环从创建项目到保存进度完整可用。
```

## 11. 单独制作增长素材

核心产品定稿后再复制项目，分别要求 Eazo 生成：

- 小红书 6–9 页案例卡模板；
- 抖音 9:16 流程演示分镜；
- X 的前后对比图与每周实验卡；
- Reddit 长案例中的流程图；
- 学生测试落地页。

增长素材只能使用已经核实的能力和获得授权的案例，不能反过来污染核心产品流程。
