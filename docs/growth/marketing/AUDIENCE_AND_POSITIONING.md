# 目标受众与首发定位

状态：内部策略草案

## 唯一首发目标

TryRevive 首发阶段只聚焦一个人群：

> 正在推进课程、竞赛、作品集或科研项目，项目已经停滞，并且近期存在明确提交节点的在校大学生。

这里的“在校大学生”包括高校专科、本科和研究生。独立开发者、职场知识工作者、成熟团队和泛效率工具用户不是前三个月的主动获客对象。

## 90 天增长目标

从正式增长启动日起连续 90 天：

> 获取 1,000 名估算独立激活大学生用户。

该数字是增长目标，不是当前成绩，也不代表已经承诺能够实现。

### “激活一名学生”的默认计数口径

一名用户需要同时满足：

1. 自主确认自己目前是高校在读学生；
2. 在 TryRevive 中带入至少一个真实停滞项目；
3. 完成首次项目恢复现场，并接受或修改出一个可执行的下一步；
4. 在 24 小时内实际开始该动作。

单纯访问页面、关注社交账号、加入群聊或只打开产品，不计入 1,000 名用户目标。

同一学生只计一次，不因创建多个项目重复累计，也不收集学号。当前本地优先环境只能按获得同意的假名化标识估算去重，无法可靠识别清缓存、多浏览器和多设备重复，因此对外应称“估算独立激活学生”，不能声称已经验证了 1,000 个独立自然人。

### 质量指标

以下指标用于判断获客是否带来真实价值，不替代 1,000 人增长目标：

- 三分钟内获得可接受下一步的比例；
- 7 天内产生学生本人认定为实质推进成果的比例；
- 30 天内再次实质推进同一项目的比例；
- 回流时无需重新解释全部背景的比例；
- 建议修改、拒绝与主动暂停或放弃的原因。

正式开始计算 90 天目标前，需要具备获得用户同意的去标识、假名化事件统计或等价测量方案。当前仓库尚未提供已经验证的线上增长统计，不能用访问量推测用户数。

详细定义与 90 天执行计划分别见 [`../../product/METRICS_AND_EXPERIMENTS.md`](../../product/METRICS_AND_EXPERIMENTS.md) 和 [`../90_DAY_1000_STUDENTS.md`](../90_DAY_1000_STUDENTS.md)。

## 创业者的角色：参与者，不是第二 ICP

创业者是创始人当前能够接触的重要人群，但前三个月不与大学生并列成为产品画像。创业者可以作为：

- 产品和商业判断的访谈对象；
- 校园社团、比赛、导师和学生创作者的连接节点；
- Build in Public 的同行反馈者；
- 愿意转介绍真实学生项目的分发伙伴。

创业者反馈不能因为表达更专业、声音更大，就覆盖真实学生的行为证据；非学生创业者不计入 1,000 名目标。仍在校的学生创业者按学生标准判断。

## 核心用户画像：项目型大学生

### 基本状态

- 当前是高校在读学生；
- 同时面对课程、竞赛、实习申请、作品集或科研任务；
- 首轮招募优先选择至少有一个项目已经停滞 7 天以上的学生；该时长是待验证的筛选假设，不是永久激活定义；
- 未来 90 天内存在提交、答辩、展示、比赛或申请节点；
- 已经使用过 AI、笔记、待办或代码工具，但项目仍没有持续推进。

### 典型行为

- 为项目收集了很多聊天记录、资料、代码或设计稿；
- 会列计划，但很少记录上一次实际做到哪里；
- 临近截止日期时反复重新规划，而不是完成一个小交付物；
- 打开内容平台查资料后容易偏离原任务；
- 待验证行为假设：愿意先投入 10–30 分钟完成一个明确动作，但不愿重新整理整个项目。

### 最痛的时刻

> “我知道这个项目必须继续，但我已经忘了上次做到哪里，也不知道现在做哪一步最有用。”

### 主要阻碍

1. 项目上下文散落，重新进入成本高；
2. “完成课程项目”或“做完作品集”仍然太大；
3. AI 继续生成方案，却没有形成真实交付；
4. 一次行动结束后没有证据和下一次入口；
5. 截止日期造成压力，但压力没有转化为清晰行动。

### 期望结果

- 在一次短会话中恢复项目现场；
- 明确今天唯一需要完成的交付物；
- 知道什么状态算完成；
- 留下文件、链接、文字或 commit 等证据；
- 下一次进入时直接从证据继续。

## 首发场景优先级

### P1：课程大作业与学期项目

- 截止日期明确；
- 项目周期通常跨越数周；
- 学生容易在组队、资料、代码和汇报之间丢失上下文。

### P1：竞赛、黑客松与创新项目

- 时间压力高；
- 需要快速从方案讨论进入可演示交付；
- 进展证据和下一次行动都容易验证。

### P1：作品集、实习与申请项目

- 目标重要但范围模糊；
- 学生常积累素材，却迟迟没有完成一段文案、一张案例页或一次提交。

### P2：科研训练、论文与毕业设计

- 项目周期更长；
- 上下文恢复和证据回流价值高；
- 需要在前三类场景验证后再扩大投入。

## 核心用户任务（Jobs to Be Done）

| 学生处境 | 学生真正想完成的任务 | TryRevive 的作用 |
|---|---|---|
| 课程项目停了两周 | 快速知道上次做到哪里 | 恢复目标、已有产出、阻碍和最近进展 |
| 比赛方案太大 | 找到今天能交付的一件事 | 生成带时间盒和完成标准的单步行动 |
| AI 方案越来越多 | 把讨论变成真实产出 | 限制范围并要求留下完成证据 |
| 作品集材料很散 | 完成一个可直接使用的模块 | 把模糊目标缩成文字、页面或素材动作 |
| 做过但记不清 | 下次不用重新理解项目 | 保存证据、项目状态和 Return Plan |
| 查资料容易跑偏 | 带着问题进入平台并按时回来 | 关键词直达、限时浏览和回流提示 |

## 首发定位陈述

对于拥有课程、竞赛、作品集或科研项目，却因为上下文断裂而不知道从哪里继续的在校大学生，TryRevive 是一个学生项目复活工具。它先恢复项目现场，再把下一步约束成一个可执行、可验证的动作，并保存证据与下一次入口。不同于普通待办工具或开放式聊天 AI，TryRevive 不继续扩展计划，而是帮助学生完成眼前唯一的真实交付物。

## 核心信息

### 主标语

让搁置的大学项目重新动起来。

### 一句话价值

找回上次做到哪里，完成今天最关键的一步。

### 学生能够立即理解的结果

- 不再重新翻完所有群聊、文档和代码；
- 不再把“完成整个项目”当作下一步；
- 每次至少留下一个真实产出；
- 临近截止日期时，知道今天先做什么。

## 前 1,000 名用户的学习原则

阶段数字、周目标和资源分配只由 [`../90_DAY_1000_STUDENTS.md`](../90_DAY_1000_STUDENTS.md) 维护。本画像文档只保留一个不变原则：先确认问题，再确认激活和 7 天实质成果，最后才扩大；不因为追求人数重新扩展到泛人群。

## Build in Public 渠道原则

首轮假设是用小红书与抖音直接验证中国大学生需求，用 X 与 Reddit 研究语言、记录学习并获得转介绍；最终以激活、7 天实质成果和创始人时间判断。所有平台格式、频次、规则与内容码只在 [`../BUILD_IN_PUBLIC_PLAYBOOK.md`](../BUILD_IN_PUBLIC_PLAYBOOK.md) 维护。

## 暂不聚焦

- 已毕业的独立开发者和职场知识工作者；
- 只需要通用待办、日历或笔记功能的人；
- 需要成熟企业权限和团队审计的组织；
- 希望产品自动接管全部决策和外部操作的用户；
- 寻找注意力障碍诊断、治疗或医疗建议的人。

## 沟通顺序

1. 先说大学生正在停滞的具体项目：课程、竞赛、作品集或科研。
2. 再说“找回上次做到哪里，完成今天最关键的一步”。
3. 用一个真实交付物和完成证据说明产品价值。
4. 最后再介绍注意力守护和 AI 辅助，避免稀释学生项目复活的主定位。
