# TryRevive 产品介绍

状态：Marketing 内容底稿，尚未批准公开发布

产品类别：大学生项目复活工具

## 一句话介绍

TryRevive 帮助在校大学生找回课程、竞赛、作品集或科研项目的上下文，把模糊的“继续做”缩小成一个有完成标准的微动作，并留下证据和回流点，让下一次继续不再从空白开始。

## 我们解决的问题

大学生项目停滞往往不是因为学生没有目标，而是因为：

- 上次做到哪里已经记不清；
- 文件、聊天、代码和计划散落在不同工具；
- 下一步太大，不知道从哪里开始；
- 项目可能已经不值得继续，或者真正缺的是技能、反馈、伙伴和依赖；
- AI 生成了很长的计划，却没有形成真实交付物；
- 做完一次动作后没有保存证据，几天后又要重新理解项目；
- 打开内容平台寻找资料时，被推荐流带走了注意力。

传统待办工具通常要求用户已经知道“要做什么”，通用聊天 Agent 又容易继续扩展计划。TryRevive 从更早一步开始：先恢复项目现场，再决定此刻唯一值得执行的动作。

## TryRevive 如何工作

1. **恢复现场**：通过不超过 5 个核心问题梳理项目、最近产出、截止节点、当前阻碍和可用时间。
2. **判断项目**：允许继续、缩小目标、求助、暂停或放弃，不默认所有项目都必须复活。
3. **必要时问清卡点**：仅在信息不足或建议被拒绝时追加最多 3 个可跳过的问题。
4. **确认下一小步**：把下一步限制为一个具有时间盒和完成标准的动作，允许用户缩小、替换或修改。
5. **立即执行**：使用简洁的行动页和计时减少启动摩擦。
6. **留下进度**：保存文字、链接、文件名或代码产出，并让学生判断它是否构成实质推进。
7. **安排回流**：记录下一次从哪里继续，避免项目再次回到空白状态。

核心闭环是：

> 第一次复活：恢复现场 → 判断项目 → 确认一个下一小步；持续推进：执行 → 留下进度 → 安排回流 → 从上次成果继续。

内部可以把这两个阶段称为 `Revive → Loop`，学生端只使用“复活项目”“下一轮”和“从上次继续”等自然语言。

## 首发目标用户

首发阶段只面向高校在读学生，优先服务：

- 正在完成课程大作业或学期项目的学生；
- 正在参加竞赛、黑客松或创新项目的学生；
- 正在准备作品集、实习或申请材料的学生；
- 正在推进科研训练、论文或毕业设计的学生；
- 使用过 AI、Notion、GitHub 或待办工具，但项目仍停滞的学生。

这些学生至少有一个已经停滞的真实项目，并在未来 90 天内面临提交、答辩、展示、比赛或申请节点。其他个人创作者和知识工作者属于未来可能扩展的人群，不是前三个月的主动获客对象。

创业者可以参与访谈、提供产品反馈、连接校园资源或转介绍学生，但不是第二个首发画像，也不计入 1,000 名学生目标。

## 当前产品能力

仓库记录的公开 MVP 包含：

- 对话式与表单式项目复活；
- Revival Brief 和规则驱动的微动作；
- 行动计时、完成证据、继续行动与短冲刺；
- 项目列表、暂停与恢复、周复盘和 JSON 导出；
- 关键词直达、常用应用入口、限时浏览与回流提示；
- 冥想空间、桌宠和可降级的 AI 心语；
- Chrome Extension MV3 原型；
- 公开公众号文章的本地知识库实验。

本地已验证、但尚未批准上线的 V3 Revival Core 进一步加入：

- 结构化 ProjectState v2；
- 具有时间盒和完成标准的 Action Contract；
- 上下文快照、证据可信等级和 Return Plan；
- 公开 GitHub 仓库上下文与 commit/PR 证据判断；
- JSON 合并和系统日历文件导出。

条件式“帮我问清楚”和内部证据门控学习循环目前是产品规格与验证方向，不能描述为已经上线的能力。

对外使用前必须根据 [`FACT_SHEET.md`](FACT_SHEET.md) 核对版本状态。

## 产品差异

- **不是另一张待办清单**：它服务于用户还不知道下一步是什么的时刻。
- **不是更长的 AI 计划**：一次只确定一个动作，并要求明确完成标准。
- **不只关注开始**：动作完成后还要留下证据和下一次回流点。
- **不把自述伪装成验证**：产品区分用户声明、可观察结果和可验证证据。
- **核心流程不依赖远程 AI**：AI 或第三方服务不可用时，本地恢复与行动闭环仍可运行。

## 数据与信任边界

- 当前数据默认保存在用户的浏览器中，可由用户主动导出。
- 产品不会自动修改用户的外部文件、提交代码或发送消息。
- 任何外部写操作都应单独取得授权。
- 当前产品不能被描述为跨设备备份或正式云存储服务。
- TryRevive 是生产力工具，不是医疗、心理治疗或诊断产品。

## 当前阶段

仓库 README 记录公开 MVP 体验地址；V3 Revival Core 是本地验证候选版，尚未批准推送或部署。首发增长目标是从正式启动日起 90 天内获取 1,000 名完成首次恢复、接受或修改出下一小步并在 24 小时内开始动作的估算独立在校学生。产品质量另以 7 天实质成果和 30 天再次推进衡量。该数字是目标，不是当前用户成绩；本地环境的去重存在限制。任何活动页、媒体稿或报名材料在发布前都应重新确认实际线上版本。
