# 四平台 Build in Public 执行手册

状态：渠道实验草案

更新日期：2026-08-02

## 1. 核心原则

Build in Public 不是每天汇报写了多少代码，而是公开一个可验证的学习循环：

`真实学生问题 → 本周改动 → 使用结果或失败 → 下一项实验`

所有内容都回到唯一 ICP：有真实停滞项目的在校大学生。首轮假设是创业者主题内容不超过总内容主题的 20%，这不是 X/Reddit 的渠道占比；这类内容也必须能带来学生反馈、转介绍或更好的产品判断。

四个平台不能复制同一篇文案。每周只选一个产品实验，再按各平台原生表达改写。

## 2. 每周四个内容支柱

1. **真实失败**：一个学生项目为什么停，不包装成励志故事；
2. **产品改动与理由**：只解释一个变化以及它解决的摩擦；
3. **经授权并去标识的结果**：展示前后现场、下一小步和 7 天结果；
4. **开放问题**：询问一个具体决策，不泛泛征求“大家怎么看”。

未经授权的用户信息、学校、项目截图和原话不得发布。场景化用户故事必须注明是虚构示例。

## 3. 小红书

### 角色

中国大学生直接获客与搜索需求验证，是首轮优先验证渠道之一。

### 适合内容

- 首轮图文模板假设：用 6–9 页表达 `为什么项目停了 → 3 个恢复问题 → 今天下一步 → 7 天结果`；
- 课程项目、竞赛 Demo、作品集的前后对比；
- 大学生创始人的真实开发日记，但每篇必须回答学生能得到什么；
- 可收藏的“项目重新进入清单”，不做泛效率鸡汤。

### 示例标题

以下数字只是结构占位，发布时必须替换为真实、可核验数据，或改成不含具体数字的虚构场景标题：

- `大作业停了两周，我没有重做计划，只先找回这 4 件事`
- `AI 给了我 30 条建议，真正让竞赛项目动起来的是这一小步`
- `作品集不是做不完，是你每次回来都从零开始`

### CTA

`如果你有一个停了至少 7 天的课程/竞赛/作品集项目，可以带真实项目完成一次测试。`

不使用微信、QQ、二维码、谐音联系方式或站外水印规避平台规则。发布前核对[小红书当前内容规则](https://pgy.xiaohongshu.com/help/detail?id=6495c527d1eedeeb48fb18b1f875650e&userType=4)及账号界面中的最新要求。

## 4. 抖音

### 角色

快速测试痛点表述和真实流程演示。

### 首轮视频结构模板

以下 35 秒结构是待验证模板，不是平台规律：

1. 0–3 秒：真人说出具体痛点；
2. 3–10 秒：展示真实项目材料，而不是炫功能；
3. 10–25 秒：恢复现场和下一小步；
4. 25–35 秒：展示结果或失败；
5. 结尾只问一个问题：`你最卡在哪一步？`

### 示例脚本

以下数字仅为结构占位，发布时必须替换为真实、可核验数据：

> 我这个课程项目停了 18 天。问题不是不会写，而是忘了上次到底做到哪里。我先写下最后一个真实成果、最近截止时间和今天只有 15 分钟，TryRevive 给出的下一步不是“完成登录”，而是“复现一次失败并保存错误信息”。如果你的项目也停了，你最卡的是忘了现场、任务太大，还是其实不想做了？

挂载或锚点文案必须与实际功能一致，避免夸张营销和站外联系方式；参考[抖音开放平台短视频挂载规范](https://partner.open-douyin.com/docs/resource/zh-CN/mini-app/operation/platform-capabilities/video/mount-usage-spec/)。

## 5. X

### 角色

记录英文 Build in Public、连接 student makers，并获得创业者反馈和转介绍。它不是首轮中国大学生获客主渠道。

### 适合内容

- 一张真实界面或去标识流程图 + 一个洞察 + 一个具体问题；
- 每周数据与失败 thread；
- `hypothesis → change → result → next experiment`；
- 英文学生项目恢复案例。

### 示例模板

> Hypothesis: students abandon stalled projects because the next step is too large.
>
> What we changed: added “continue / narrow / ask for help / pause / abandon” before generating a step.
>
> What happened: [sample and evidence, or “not enough data yet”].
>
> Next question: when should the product ask one more clarifying question instead of giving a step immediately?

允许发布正常链接，具体格式见 [X 的发链接说明](https://help.x.com/en/using-x/how-to-post-a-link)；但不批量回复、提及或私信，不使用无关热门标签，并遵守 [X Authenticity policy](https://help.x.com/en/rules-and-policies/authenticity)。

## 6. Reddit

### 角色

研究真实语言、替代方案和失败案例；适合长文本，不适合跨社区复制广告。

### 发布方式

- 先阅读每个 subreddit 的独立规则；
- 明确披露自己是产品构建者；
- 以完整复盘和具体问题为主，链接不是主体；
- 优先使用允许反馈的固定 thread，或先联系 moderator；
- 不复制同一内容到多个无关社区。

### 示例结构

> I’m building TryRevive, so I’m biased. I’m testing a narrow assumption with students who have a real project stalled for 7+ days: whether recovering the last concrete artifact and choosing one meaningful next step helps more than generating another plan. Here is what failed in our current flow: [...]. For people who have restarted a course or portfolio project, what information did you actually need before you could continue?

Reddit 将重复或未经请求的大规模互动视为 spam，并要求尊重各社区规则；参考 [Reddit Spam policy](https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam)。

## 7. 一周一个实验的四平台改写

假设：`先判断项目是否值得继续，会减少无意义的小任务。`

| 平台 | 原生表达 |
|---|---|
| 小红书 | 首轮测试 7 页图文：停滞现场、五种判断、下一步、7 天结果 |
| 抖音 | 真人痛点 + 选择“缩小/暂停”过程 + 结果 |
| X | hypothesis/change/failure/next question thread |
| Reddit | 完整复盘、披露身份、询问他人真实恢复经历 |

四个平台使用同一个实验 ID，但拥有独立内容码。

## 8. 衡量什么

平台比较按以下顺序：

1. 内容归因的合格学生；
2. 合格学生→激活；
3. 激活→7 天实质成果；
4. 30 天继续；
5. 创始人时间/激活学生；
6. 创始人时间/7 天实质成果；
7. 违规、投诉和错误人群比例。

播放量、点赞、粉丝和创业者称赞只作为诊断信号，不作为目标。

## 9. 合规与信任边界

- 不制造虚假用户、评价、学校合作或效果数字；
- 不要求学生上传学生证；
- 不公开个人数据、项目材料或聊天截图，除非取得明确授权；
- 使用 AI 生成或显著编辑的内容时，按各平台与适用地区规则分别标识；在中国发布前核对[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)；
- 付费、赠送权益或合作内容必须按适用规则披露关系；在中国发布商业内容前核对[《互联网广告管理办法》](https://www.samr.gov.cn/ggjgs/tzgg/art/2024/art_fb2f2f9b53f04dc294df2105b2e050a0.html)；
- 不通过批量私信、自动评论、无关标签或多个账号制造热度；
- 不把 90 天 1,000 人写成已经达成。

发布前重新核对平台最新规则；平台规则会变化，本手册不是永久合规保证，也不是法律意见。
