# ADR-001：模型供应商解耦与本地降级

状态：接受为技术方向；不属于学生 MVP 的 P0 用户功能

更新日期：2026-08-02

## 背景

前端若直接依赖他人控制的 API、密钥或固定模型名，会让不可控凭据成为核心路径。这个问题需要技术决策，但不应占据学生产品 PRD，也不能被包装成用户价值。

## 决策

- 核心的恢复、下一小步、进度和回流流程可在远程模型不可用时运行；
- 前端不得保存供应商密钥；
- 需要远程模型时，只调用 TryRevive 自己控制的 BFF/网关；
- 供应商、模型、超时和降级顺序在服务端配置；
- 外部连接默认只读，产生副作用的动作单独授权；
- 在 5–20 个真实学生项目证明价值前，不把多供应商网关、Agent Router 或连接器平台作为 P0 建设重点。

## 结果

好处：避免单一非自有凭据成为关键依赖，核心体验可降级，密钥边界更清楚。

代价：需要维护自己的接口层；真实云同步、提醒和私有连接仍然依赖外部服务，因此不能使用“彻底解除所有 API 依赖”这类不准确表述。

## 触发实施的条件

只有当远程模型或连接器已经明确改善学生 MVP 主指标，并且本地规则无法满足时，才建设相应后端能力。任何实现仍需单独的安全、隐私和成本评审。
