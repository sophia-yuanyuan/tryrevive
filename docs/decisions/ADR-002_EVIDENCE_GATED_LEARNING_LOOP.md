# ADR-002：证据门控的产品学习循环

状态：接受为产品学习边界；尚未实现自动化

更新日期：2026-08-02

## 背景

“RSI Agent”这个名称并不唯一。与 TryRevive 最相关的两种公开实现是：

- Weco AIDE²：内环完成任务，外环改进内环 agent 的 harness；候选只有在固定成本和不可见评测上更好时才保留。
- OpenCrabs RSI：记录工具结果和用户纠正，分析重复模式，并更新部分“脑文件”。其文档允许某些自改无需人工批准。

这些工作带来的启发是：真正有用的“自我改进”依赖反馈账本、明确评测、版本、拒绝大量无效改动和可回退，而不是让模型无限循环生成新提示词。

TryRevive 面对的“项目是否实质推进”是模糊且由用户判断的结果，不能直接复制无人批准的线上自修改机制。

## 决策

TryRevive 使用三层模型：

```text
Revive：找回现场 → 判断是否值得继续 → 确认下一小步
Loop：执行 → 留下进度 → 安排回流 → 从成果继续
Learn：聚合失败模式 → 提出改动 → 评测 → 人工批准、发布或回滚
```

其中 Revive 和 Loop 是用户生命周期；Learn 是内部产品研发流程，不是学生端功能。

## Learn 的最小流程

1. 记录获得同意的去标识、假名化行为事件和用户纠正；
2. 每周人工检查重复失败模式；
3. 一次只提出一个小范围的规则、问题树或文案修改；
4. 先在可见开发案例集上调试，再在候选不可见的晋级集上评测；
5. 通过小流量实验检查产品主指标和护栏；
6. 产品负责人明确批准或拒绝；
7. 发布时记录 `policyVersion`；
8. 指标恶化、隐私或伤害护栏触发时回滚。

## 隔离评测集

评测拆成两部分：

- 可见开发集：用于定位问题和调试候选；
- 不可见晋级集：候选生成过程不能读取，用于决定是否有资格进入小流量验证。

候选只能修改白名单内的规则、问题树、提示词或文案。评测器、指标定义、原始事件日志、成本预算和不可见晋级集必须只读，不能由候选改写。

至少覆盖：

- 上下文丢失；
- 下一步过大；
- 项目已无价值；
- 缺技能、反馈、伙伴或权限；
- 明知下一步但不愿执行；
- 应暂停或放弃；
- 课程、竞赛、作品集和毕业设计；
- 建议被学生修改或拒绝；
- 回流后项目状态发生变化。

评测不能只看动作完成率，还必须看学生认可的推进价值、7/30 天继续、无需重新解释、提醒打扰和卡点诊断退出。

## 允许与禁止

### 允许

- 自动汇总获得同意的假名化事件；
- 自动发现重复拒绝原因；
- 自动生成改动提案和影响说明；
- 自动在沙盒中的开发集与隔离晋级集运行评测；
- 自动建议回滚。

### 禁止

- 未经人工批准直接修改生产提示词、规则或代码；
- 修改评测器、指标定义、原始事件日志、预算或不可见晋级集；
- 为提高完成率而降低“实质推进”的定义；
- 使用未同意上传的原始项目文字训练或评测；
- 将相关性写成因果结论；
- 对学生公开宣传“自我进化 Agent”或“RSI”，除非以后确实实现且能准确解释。

## GrillMe 的关系

`grill-me` 是逐题澄清决策的方法，不等于 RSI。

- 创始人端：可用完整版工作流压力测试 PRD、增长假设和设计选择；
- 学生端：改写为最多 3 问、可跳过、低压力的“帮我问清楚”；
- 学生端的回答和退出只作为 Learn 的输入信号，不能直接触发生产自改。

官方 `grill-me` 文件只是调用 `/grilling` 的入口；若以后安装到开发环境，必须同时保留实际 `grilling` 工作流和 MIT 许可要求。本次决策不授权下载或安装第三方 skill。

## 分阶段实施

- 0–100 名：创始人手动分析；产品只使用确定性条件问题；
- 101–400 名：记录拒绝原因、策略版本和 Revive→Loop 结果；
- 401–1,000 名：每周最多一个人工批准的策略实验；
- 1,000 名后：只有在数据质量和评测稳定时，才考虑自动生成提案，仍不自动发布。
