# TryRevive 非技术纵向验收清单

状态：`CURRENT`（本地沉浸链路）+ `PARTIAL CURRENT`（收费云端链路）

适用分支：`codex/frontend-platform`

这份清单不要求看代码。你只需要下载 Windows 安装包，用一个真实但不敏感的烂尾项目走完一次，并记录“我点了什么、期望什么、实际发生什么”。自动测试通过不等于你已经喜欢这个体验；最后决定仍由你做。

## 1. 先确认拿到的是正确安装包

1. 在 GitHub Actions 的 `CI` 中确认 `web` 和 `windows-package` 都是绿色，并确认该次运行的 commit SHA 正是你要验收的版本。没有对应 SHA 的绿色运行就先停止，不能拿旧安装包代替。
2. 下载 artifact：`tryrevive-windows-unsigned`。
3. 解压后应有：
   - `TryRevive-Setup-0.8.0-x64.exe`：可选择安装目录的安装版；
   - `TryRevive-Portable-0.8.0-x64.exe`：免安装版；项目数据仍保存在 Windows 用户数据目录，不是“删除 EXE 就删除全部数据”的完全便携模式；
   - `SHA256SUMS.txt`：两个文件的校验值。
4. 当前安装包未做商业代码签名，Windows 可能显示“未知发布者”。只在你自己的测试电脑运行；公开分发前必须补代码签名。

## 2. 用一个真实项目走完整主链路

准备三个名称，例如“黑客松报名”“证书考试”“作品集页面”，但不要先上传身份证、合同或未公开商业材料。

### 启动和收纳

- 双击启动，预期：TryRevive 直接全屏；页头有“退出全屏”，按 `Esc` 也能退出，之后可点“进入全屏”回来。它不是锁屏。
- 在“所有还在心里的项目”中每行写一个名称，点击“收下这 3 个项目”。
- 关闭并重新打开，预期：三个项目都还在，没有重复。

### 找回现场和决定

- 选择一个项目，填写“上次最后完成了什么”“具体卡在哪里”“最近节点”“为什么仍值得继续”。
- 选择继续、缩小、求助、暂停或放弃。
- 预期：系统给出一件 5–20 分钟、能留下可见结果的小事；你可以修改后再接受。
- 不通过：只有“继续努力”“再研究一下”之类空话，或用羞辱语言逼迫继续。

### 以唱针进入专注

- 点击“以唱针进入全屏专注”。
- 即使 Windows 开启“减少动画”，也要先看到上次现场和当前小步，再按住唱针按钮约 0.8 秒。
- 预期：只有按住完成后计时才开始；提前松开不会偷偷开始计时。
- 鼠标、触摸、空格和 `Enter` 都使用同一套 0.8 秒保持规则，短按 `Enter` 不能绕过确认。
- 专注中按 `Esc`，预期：随时离开，已保存的项目内容不丢失。
- 再次进入，预期：正在进行的动作能继续，不需要重述全部背景。

### 留下结果和获得唱片

- 点击“我留下了一个结果”，写下本次实际留下的文字、文件或决定。
- 完成项目后选择当时心情，进入“黑胶星球”。
- 点击封套取出唱片，再主动播放或导出 WAV。
- 预期：音乐与这次项目、实际行动时长和所选心情有关；刷新后唱片仍在。
- 对另一个测试项目选择放弃，预期：它进入黑洞历史，不被删除，也不被写成“失败者”。

## 3. 单独验收 Windows 偏离提醒

1. 在专注页选择本次允许的软件，例如 Chrome 和 Word。
2. 点击“开启本次偏离提醒”。未点击前不应监测。
3. 切到一个未允许的软件并停留超过 12 秒。
4. 预期：TryRevive 回到全屏提示，但必须同时能 `Esc` 离开、结束守护、说明“这是必要工作”或回到当前小步。
5. 结束专注或关闭应用后，守护不得在后台自动恢复。

这一步只判断前台应用名，不能判断同一个浏览器中打开的是工作页还是娱乐页，也不会读取按键、网页或窗口标题。

## 4. 单独验收摄像头手势

1. 进入“黑胶星球”，先确认页面写着“摄像头默认关闭”。
2. 主动同意后开启，预期：始终可见本机预览和识别状态。
3. 手掌移动用于旋转；握拳稳定停留用于选择；拇指向上用于打开。握拳或拇指保持时应看到进度，触发后必须先松手，不能每隔一秒连续触发。
4. 点击“关闭摄像头”或离开页面，预期：预览停止。
5. 鼠标、触摸和键盘必须始终可用；手势识别失败不能让页面无法操作。

## 5. 当前云端链路应该怎样验收

当前只验收“不会误上传”“账本规则”和“服务端适配器自动测试”，不能把真实 OpenAI 识别写成已经上线：

- 首次打开时，“项目文件夹”“说一段话或上传现有材料”“本地文字”必须在同一个入口页可见；未配置可信云端地址时，语音/附件区域必须直接显示“当前不会上传任何内容”。
- 页面不能要求普通用户填写 API Key，也不能让用户选择供应商模型。
- 手工找回现场、专注、证据、回流、黑胶和音乐不能因为云端不可用而被锁住。
- 当前服务入口默认关闭真实处理方；只有服务端同时配置显式启用开关、OpenAI secret 和审核过的分析模型后才允许接收内容。
- 打包版只接受未来审核过的 `https://api.tryrevive.online`；任意其他 HTTPS 地址不能通过环境变量冒充 TryRevive 云端。

接通测试服务后再继续验收：兑换额度 → 只用匿名元数据报价 → 用户再次确认 → 服务端先预留额度 → 上传 → 返回恢复草稿 → 进入统一的“我猜你做到这里”确认页 → 成功结算或失败退款。上传确认页必须明确写出 OpenAI 是处理方、Responses 请求设置为 `store: false`，以及默认安全日志仍可能保留最多 30 天；没有这些文字就不要上传真实材料。

## 6. 单独验收数据不会被误覆盖

1. 先导出一份 JSON 备份并保留。
2. 再尝试导入一个故意写坏的 `.json` 测试文件。
3. 预期：TryRevive 明确说无法读取，现有项目仍在；刷新或重启后也仍在。
4. 桌面版遇到未来版本或损坏主存档时，会优先恢复有效 `.bak` 并保留异常原件；若主备都无法验证，只显示恢复入口，禁止新建、修改和导出空白数据。

不要为了人工验收直接破坏你唯一的真实存档。未来版本、损坏主存档和 `.bak` 恢复由自动化测试覆盖；人工只需使用专门的测试数据。

## 7. 当前自动验证证据

不要记住一组会过期的测试数字。每次只在 GitHub Actions 中打开你准备下载的那个 commit，并核对同一个 `CI` 运行中的 `web` 与 `windows-package` 都为绿色。交付报告必须另外写明该 commit 的单元测试数、Worker 测试数、Electron E2E 数和安装包 SHA-256；任一 SHA 对不上就停止验收。

自动测试应至少覆盖：无效 JSON 不覆盖现有项目、全屏可退出、项目重启后仍在、仓库 Confirm/Correct、专注完成后的成果识别、黑胶实播和 WAV 导出、MediaPipe 只从应用资源加载、云端重复请求只扣一次、上游失败退款、客户端不出现 API Key，以及云端处理开关默认关闭。

这些数字只对应执行它们的 commit。真实扬声器是否发声、真人手势是否适合你、NSIS 安装/卸载体验和跨软件拉回仍需要人工验收。

## 8. 最终只回答这八个问题

| 问题 | 是 / 否 |
|---|---|
| 一打开就是全屏，但我随时能退出吗？ | |
| 我能一次放下多个烂尾项目并在重启后找回吗？ | |
| 系统能把一个项目缩成我愿意开始的小步吗？ | |
| 唱针进入方式让我更容易开始，而不是增加仪式负担吗？ | |
| 偏离提醒能拉我回来，同时不会羞辱或困住我吗？ | |
| 完成后的黑胶、音乐和项目真实状态一致吗？ | |
| 摄像头默认关闭，关闭后真的停止吗？ | |
| 云端未接通时，本地完整链路仍能使用吗？ | |

任一项为“否”，只记录四句话：`所在页面`、`刚才点的按钮`、`我原本期待`、`实际发生`。不需要解释代码原因。
