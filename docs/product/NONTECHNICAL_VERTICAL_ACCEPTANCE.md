# TryRevive 非技术纵向验收清单

状态：`CURRENT`（本地文字、仓库、PDF、DOCX、Windows 离线语音与沉浸链路）+ `PARTIAL CURRENT`（收费云端链路）

适用分支：`codex/frontend-platform`

这份清单不要求看代码。你只需要下载 Windows 安装包，用一个真实但不敏感的烂尾项目走完一次，并记录“我点了什么、期望什么、实际发生什么”。自动测试通过不等于你已经喜欢这个体验；最后决定仍由你做。

## 0. 这轮先只验收这一条主链路（10–15 分钟）

先不要验收支付、手势、黑胶星球细节或云端模型。它们不能代替下面这条 inference-first 主链路。准备一个**没有密钥、身份证、合同或私密资料的测试项目文件夹**，里面至少有 `README.md` 和一个你可以修改的正文或代码文件。不要直接拿唯一一份真实项目做破坏性测试。

### 第一次进入：TryRevive 是否真的理解了现场

1. 打开 Windows 桌面版。预期：直接全屏，但 `Esc` 随时可以退出。
2. 在统一入口选择“项目文件夹”，再选择测试文件夹。预期：页面说明只做有限、安全的本机扫描，不上传文件，不显示绝对路径，也不读取 `.env`、凭据文件、依赖目录或符号链接外部内容。
3. 等待出现“我猜你做到这里”。先不要看代码，只核对五件事：
   - 最开始想完成什么；
   - 已经做到哪里；
   - 卡在哪里；
   - 为什么可能停住；
   - 唯一一个 5–20 分钟的下一步。
4. 如果基本准确，点“正确，继续”；如果有一处不准确，点“修改”，只改错的地方，再点“保存修改”和“正确，继续”。
5. 预期：确认前不会创建正式项目；确认失败时草稿仍在，也不会出现半个项目。确认后只出现一个项目和一个下一步。

也可以在 Windows 桌面版点击“用 Windows 本机语音说”，主动授予麦克风权限后，说出最初目标、做到哪里和卡点，再点击“停止并本机理解”。预期：使用随应用打包的离线模型，不要求 API Key、不上传录音；随后进入同一个“我猜你做到这里”确认页。拒绝麦克风、没有录到清晰声音或转写失败时，仍可继续输入文字，不创建空项目。

这一段通过的标准不是“AI 写得像人”，而是：**你不需要重讲全部背景，只改很少内容，就愿意接受它给出的下一步。** 如果它虚构了已经完成的成果、把猜测写成事实，或下一步只是“继续努力/继续研究”，直接判为不通过。

### 进入专注：系统是否只留下现在这一件事

6. 点击“以唱针进入全屏专注”，按住约 0.8 秒。提前松开不应开始；完成保持后才开始计时。
7. 预期：专注页只保留当前动作、完成标准、计时和退出入口。`Esc` 能离开，离开后项目不丢失。
8. 在专注期间，真实修改刚才文件夹中的一个可读文件并保存，例如给 `README.md` 增加一句真实进展。不要只改文件时间，也不要故意删除文件。
9. 回到 TryRevive，点击“我留下了一个结果”。

### 留下成果：系统是否把观察和结论分开

10. 预期：TryRevive 只说“本次有限扫描检测到哪些可读文件内容变化”或“哪些路径本次新出现在扫描结果中”，不会声称“项目已完成”“文件已新建”“文件已删除”或“质量已通过”。
11. 路径和说明正确时点“正确，留下这条记录”；说明不准确时点“修改”，写下真实结果后保存。机器观察到的路径与自己写的成果说明应同时保留。
12. 如果没有检测到可读变化或扫描失败，预期：仍能手写成果，不会阻断流程，也不会把“没检测到”说成“你什么都没做”。
13. 设置“下次从这里继续”。预期：默认入口优先指向刚才确认的变化文件；你可以编辑它。
14. 关闭并重新打开 TryRevive，选择这个项目继续。预期：十秒内看到刚才的成果和下次入口；下一步从这个入口继续，不重复最初那条已经完成的建议。

### 奖励边界：不能为了动画伪造完成

15. 完成一个小步只留下成果记录和下次入口，**不会自动把整个项目标记完成，也不会自动生成完整黑胶奖励**。
16. 只有你在项目完成页明确选择“这个项目已经完成”后，才生成该项目的完整黑胶；选择暂停或放弃必须保留历史，不伪装成完成。

### 一眼判断结果

| 关键问题 | 通过标准 |
|---|---|
| 它理解了吗？ | 我只需确认或少量修改，不必重讲全部背景 |
| 它给的下一步能开始吗？ | 5–20 分钟，有一个可见完成标准 |
| 专注是否可控？ | 保持后才开始，`Esc` 随时退出，数据不丢 |
| 成果识别诚实吗？ | 只报告有限扫描观察，不替我宣布完成或质量 |
| 下次能接上吗？ | 重启后看到真实成果和具体入口，不重复旧动作 |
| 奖励真实吗？ | 只有我明确确认整个项目完成才生成完整黑胶 |

任一项不通过，不要解释技术原因，只把下面六行发给 Codex：

```text
验收版本（安装包对应 commit）：
所在页面：
刚才点的按钮：
我原本期待：
实际发生：
关闭重开后是否仍然如此：是 / 否
```

Web 版可以验收“粘贴文字／上传可复制文字的 PDF 或 DOCX → 本地草稿 → 确认或修改 → 专注 → 手写成果 → 下次继续”，但浏览器不能选择并持续绑定本机项目文件夹，也不提供 TryRevive 打包的离线语音模型，所以**自动成果识别和离线语音必须使用 Windows 桌面版验收**。上传音频文件、扫描图片 OCR 和更深的真实云端理解仍由 staging 模型审核与远端 E2E 门禁控制；安全关闭时不能把这些能力写成已经可用。

## 1. 先确认拿到的是正确安装包

1. 在 GitHub Actions 的 `CI` 中确认 `web` 和 `windows-package` 都是绿色，并确认该次运行的 commit SHA 正是你要验收的版本。没有对应 SHA 的绿色运行就先停止，不能拿旧安装包代替。
2. 下载 artifact：`tryrevive-windows-unsigned`。
3. 解压后应有：
   - `TryRevive-Setup-0.8.0-x64.exe`：可选择安装目录的安装版；
   - `TryRevive-Portable-0.8.0-x64.exe`：免安装版；项目数据仍保存在 Windows 用户数据目录，不是“删除 EXE 就删除全部数据”的完全便携模式；
   - `SHA256SUMS.txt`：两个文件的校验值。
4. 当前安装包未做商业代码签名，Windows 可能显示“未知发布者”。只在你自己的测试电脑运行；公开分发前必须补代码签名。

## 2. 用一个真实项目走完整主链路

准备三个名称，例如“黑客松报名”“证书考试”“作品集页面”，但不要先上传身份证、合同或未公开商业材料。

### 启动和收纳

- 双击启动，预期：TryRevive 直接全屏；页头有“退出全屏”，按 `Esc` 也能退出，之后可点“进入全屏”回来。它不是锁屏。
- 在“所有还在心里的项目”中每行写一个名称，点击“收下这 3 个项目”。
- 关闭并重新打开，预期：三个项目都还在，没有重复。

### 找回现场和决定

- 选择一个项目，填写“上次最后完成了什么”“具体卡在哪里”“最近节点”“为什么仍值得继续”。
- 选择继续、缩小、求助、暂停或放弃。
- 预期：系统给出一件 5–20 分钟、能留下可见结果的小事；你可以修改后再接受。
- 不通过：只有“继续努力”“再研究一下”之类空话，或用羞辱语言逼迫继续。

### 以唱针进入专注

- 点击“以唱针进入全屏专注”。
- 即使 Windows 开启“减少动画”，也要先看到上次现场和当前小步，再按住唱针按钮约 0.8 秒。
- 预期：只有按住完成后计时才开始；提前松开不会偷偷开始计时。
- 鼠标、触摸、空格和 `Enter` 都使用同一套 0.8 秒保持规则，短按 `Enter` 不能绕过确认。
- 专注中按 `Esc`，预期：随时离开，已保存的项目内容不丢失。
- 再次进入，预期：正在进行的动作能继续，不需要重述全部背景。

### 留下结果和获得唱片

- 点击“我留下了一个结果”，写下本次实际留下的文字、文件或决定。
- 完成项目后选择当时心情，进入“黑胶星球”。
- 点击封套取出唱片，再主动播放或导出 WAV。
- 预期：音乐与这次项目、实际行动时长和所选心情有关；刷新后唱片仍在。
- 对另一个测试项目选择放弃，预期：它进入黑洞历史，不被删除，也不被写成“失败者”。

## 3. 单独验收 Windows 偏离提醒

1. 在专注页保持默认“严格白名单 · 立即拉回”，选择本次允许的软件，例如 Chrome 和 Word；没有选择任何白名单软件时不能启动严格守护。
2. 点击“开启本次白／黑名单守护”。未点击前不应监测。
3. 切到一个未允许的软件。严格模式预期立即拉回；如果主动改选“12 秒宽限”，才在持续偏离超过 12 秒后拉回。黑名单软件在两种模式中都立即拉回。
4. 预期：TryRevive 回到全屏提示，但必须同时能 `Esc` 离开、结束守护、说明“这是必要工作”或回到当前小步。守护不会终止其他软件。
5. 结束专注或关闭应用后，守护不得在后台自动恢复。

这一步只判断前台应用名，不能判断同一个浏览器中打开的是工作页还是娱乐页，也不会读取按键、网页或窗口标题。“严格”指名单外应用一经检测就拉回 TryRevive，不是禁止 Windows 打开软件。

## 4. 单独验收摄像头手势

1. 进入“黑胶星球”，选中一张已完成唱片，确认 3D 舞台左上角出现摄像头区域且默认关闭。
2. 主动同意后开启，预期：左上角始终可见本人预览和“本机识别 · 不保存 · 不上传”，不会挡住唱盘或唱针。
3. 张开手掌稳定保持用于打开封套；把拇指与食指在唱片上捏合用于抓取，保持捏合移动，进入唱盘后张开手指用于放盘；唱片就位后再捏取唱针并放到唱片。落针不会自动播放，仍需明确点击播放。
4. 对开封、抓盘、放盘、落针各尝试 10 次并记录成功次数；任何动作少于 8 次成功，都只能记作需要调参，不能记作通过。
5. 点击“关闭摄像头”或离开页面，预期：预览停止。
6. 鼠标、触摸和键盘必须始终可用；手势识别失败不能让页面无法操作。

## 5. 当前云端链路应该怎样验收

当前可以直接验收“不会误上传”“支付不能由客户端伪造”“隐私入口可用”和本地降级；不能把真实 OpenAI 识别或真实支付写成已经上线：

- 首次打开时，“项目文件夹”“说一段话或上传现有材料”“本地文字”必须在同一个入口页可见；未配置可信云端地址时，语音/附件区域必须直接显示“当前不会上传任何内容”。
- 页面不能要求普通用户填写 API Key，也不能让用户选择供应商模型。
- 手工找回现场、专注、证据、回流、黑胶和音乐不能因为云端不可用而被锁住。
- 当前服务入口默认关闭真实处理方；只有服务端同时配置显式启用开关、OpenAI secret 和审核过的分析模型后才允许接收内容。
- 打包版只接受未来审核过的 `https://api.tryrevive.online`；任意其他 HTTPS 地址不能通过环境变量冒充 TryRevive 云端。
- 打开“隐私与数据”，预期：能导出云端数据 JSON、核验 TryRevive 不保存上传原文，并通过明确二次输入永久删除云端账户；删除云端账户后，本地项目仍在。
- 如果云端返回支付入口，只能打开 `checkout.stripe.com`；支付页返回、刷新余额或客户端声称成功都不能自行增加额度。

接通测试服务后，先由仓库管理员运行 `Staging model quality review`：它会用 10 份中英文合成材料生成一份你能逐项勾选的 Markdown 报告。自动绿色不等于通过，你必须确认目标、真实进度、卡点、唯一下一步和“没有虚构完成”。签字后再运行 `Remote cloud acceptance`，验收兑换额度 → 匿名元数据报价 → 用户确认后的预留 → 上传 → 恢复草稿 → 重复请求不重复处理 → 上游失败退款。两个工作流都要人工确认会消耗 staging 算力；没有签字记录和绿色结果前，不要上传真实材料。

域名和生产服务由仓库管理员手动运行 `Production control-plane preflight` 验收。它必须同时看到根域、`www`、`api`、`staging-api` 可解析，所有权 TXT 与受保护 Secret 一致，网站 HTTPS 不跳出 TryRevive 域名，以及生产目录明确报告 OpenAI 和支付已启用。截至 2026-08-08，这一项预期为红灯，因为公开 DNS 尚未配置；红灯是诚实结果，不是安装包故障。

## 6. 单独验收数据不会被误覆盖

1. 先导出一份 JSON 备份并保留。
2. 再尝试导入一个故意写坏的 `.json` 测试文件。
3. 预期：TryRevive 明确说无法读取，现有项目仍在；刷新或重启后也仍在。
4. 桌面版遇到未来版本或损坏主存档时，会优先恢复有效 `.bak` 并保留异常原件；若主备都无法验证，只显示恢复入口，禁止新建、修改和导出空白数据。

不要为了人工验收直接破坏你唯一的真实存档。未来版本、损坏主存档和 `.bak` 恢复由自动化测试覆盖；人工只需使用专门的测试数据。

## 7. 当前自动验证证据

不要记住一组会过期的测试数字。每次只在 GitHub Actions 中打开你准备下载的那个 commit，并核对同一个 `CI` 运行中的 `web` 与 `windows-package` 都为绿色。交付报告必须另外写明该 commit 的单元测试数、Worker 测试数、Electron E2E 数和安装包 SHA-256；任一 SHA 对不上就停止验收。

自动测试应至少覆盖：无效 JSON 不覆盖现有项目、全屏可退出、项目重启后仍在、仓库 Confirm/Correct、专注完成后的成果识别、黑胶实播和 WAV 导出、MediaPipe 只从应用资源加载、云端重复请求只扣一次、上游失败退款、客户端不出现 API Key，以及云端处理开关默认关闭。

这些数字只对应执行它们的 commit。真实扬声器是否发声、真人手势是否适合你、NSIS 安装/卸载体验和跨软件拉回仍需要人工验收。

## 8. 最终只回答这八个问题

| 问题 | 是 / 否 |
|---|---|
| 一打开就是全屏，但我随时能退出吗？ | |
| 我能一次放下多个烂尾项目并在重启后找回吗？ | |
| 系统能把一个项目缩成我愿意开始的小步吗？ | |
| 唱针进入方式让我更容易开始，而不是增加仪式负担吗？ | |
| 偏离提醒能拉我回来，同时不会羞辱或困住我吗？ | |
| 完成后的黑胶、音乐和项目真实状态一致吗？ | |
| 摄像头默认关闭，关闭后真的停止吗？ | |
| 云端未接通时，本地完整链路仍能使用吗？ | |
| 云端导出和永久删除是否清楚，而且不会删掉本地项目？ | |

任一项为“否”，只记录四句话：`所在页面`、`刚才点的按钮`、`我原本期待`、`实际发生`。不需要解释代码原因。
