# 黑胶星球与项目音乐验收

状态：`PARTIAL CURRENT`；真 3D 替换目标见 `VINYL_RITUAL_3D_ACCEPTANCE.md`

适用版本：`codex/frontend-platform@cb2bf83`，应用版本 `0.8.0`

这份清单给不看代码的产品负责人使用。验收的不是“代码写了多少”，而是一个完成项目或放弃项目能否真实走到收藏、刷新后仍存在，并且音乐能否真的导出。

## 先知道当前边界

### CURRENT

- 完成项目时选择一种真实心情，结果保存在本机。
- 完成项目进入黑胶星球；放弃项目进入黑洞历史，记录不会删除。
- 已完成且选择心情的项目使用本地 WebGL 真 3D 仪式，可依次打开封套、取出唱片、放到唱盘、落针播放并收藏；显卡绘制失败时自动切到可操作的简化画面。
- 星球可用鼠标拖动、触摸滑动、方向键转动；所有唱片也可用 `Tab` 和 `Enter` 打开。
- 曲目根据项目身份、完成心情、每一步实际用时和成果数量确定，同一份项目数据会得到同一首曲目。
- 音乐在本机生成 48–96 秒、单声道、22.05 kHz、16-bit PCM WAV；播放和导出使用同一份 WAV。
- 网页版下载 WAV；Windows 桌面版弹出“另存为”。
- 支持减少动态效果；摄像头默认关闭，只有用户主动同意后才启动随包 MediaPipe 模型和本地预览。
- 握拳/拇指保持显示进度，一次保持只触发一次，必须松手后重新武装；鼠标、触摸和键盘始终可用。

### PARTIAL CURRENT

- 收藏总览星球仍使用浏览器 CSS 透视与三维变换，不是 WebGL 写实宇宙；真 3D 目前只覆盖单张完成唱片的开封、放盘与落针仪式。
- 音乐是本地规则合成的完整 WAV 文件，不是生成式音乐模型、多轨工程或商业发行母带。
- 如果旧项目没有记录真实开始时间，会使用当时计划分钟数作为兜底，并在代码测试中区分这两种来源。

### 仍未实现

- 真人手掌“从封套抓取唱片并放入星球”的完整空间仪式；当前手势只支持旋转、选择和打开。
- WebGL 真三维唱盘、唱针、黑洞吸积盘和可 raycast 的唱片轨道；现有 CSS 场景不会继续作为最终视觉修补。
- 由 21 点关键点驱动并经过真人成功率验收的捏取、跟随、放盘和落针。
- 经过产品负责人试听通过的原创分轨编曲；参考歌曲不会作为采样或应用资产进入仓库。
- 真实账户、充值支付和云端算力扣费。
- 面向真实用户的云端语音识别、附件理解和 LLM 分析。

## 验收路径 A：完成项目进入黑胶星球

1. 打开 TryRevive，输入一个你愿意测试的项目名称。
2. 依次填写“上次最后完成了什么”和“具体卡在哪里”。
3. 选择继续或缩小，确认下一小步，进入专注界面。
4. 点击“我留下了一个结果”，写下一条实际成果并安排下次继续。
5. 在“下次不用从头回忆”页点击“这个项目已经完成”。
6. 选择最接近当时感受的一种心情，例如“踏实的骄傲”。

算通过：

- 页面进入“这个项目已经完成”；
- 封套可以点击打开，唱片从封套侧面取出；
- 页头出现“黑胶星球”入口；
- 进入星球后，完成唱片列表中出现刚才的项目；
- 页面明确显示所选心情、记录分钟数和曲目时长。

## 验收路径 B：播放、导出与刷新

1. 在黑胶星球选中刚才的完成项目。
2. 点击“播放项目唱片”，确认设备真正发出声音；再次点击可暂停。
3. 点击“导出同一首 WAV”。
4. 网页版确认下载文件名是“项目名.wav”；桌面版选择一个位置保存。
5. 用系统播放器打开 WAV。
6. 返回 TryRevive 并刷新，或关闭桌面应用后重新打开，再进入黑胶星球。

算通过：

- 导出的 WAV 可以被系统播放器打开；
- 刷新或重启后项目、完成心情和唱片仍存在；
- 同一项目重新播放/导出的曲目参数不变；
- 取消“另存为”不会报错，也不会产生空文件。

## 验收路径 C：放弃项目进入黑洞历史

1. 新建另一个用于测试的项目并找回现场。
2. 在“现在最诚实的选择是什么？”选择“放弃”。
3. 进入黑胶星球。
4. 点击黑洞、弯折唱片，或在“黑洞历史”列表里打开该项目。

算通过：

- 项目不再出现在进行中列表；
- 它出现在“黑洞历史”，而不是被删除；
- 页面使用“已经放下”“记录仍保留”等中性文案；
- 不出现人格评价、羞辱或失败惩罚。

## 验收路径 D：不用鼠标也能完成

1. 按 `Tab` 把焦点移到黑胶星球场景。
2. 使用四个方向键转动场景。
3. 继续按 `Tab` 选中一张唱片，按 `Enter` 打开。
4. 在 Windows“设置 → 辅助功能 → 视觉效果”关闭动画效果，或在浏览器模拟 `prefers-reduced-motion: reduce` 后重复以上步骤。

算通过：

- 主要操作都有可见焦点；
- 不用鼠标也能打开项目、播放和导出；
- 减少动态效果后，自动过渡被压缩，但内容和按钮没有消失。

## 自动验证证据

- `npm run check`：类型检查、Lint、38 个前端单元测试、19 个 Worker 测试、1 个 Windows 前台监测集成测试、Web 构建和 Electron 构建全部通过。
- `npm run test:e2e`：14 个桌面/手机浏览器测试通过；其中包含完成项目、选择心情、黑胶播放时间真实前进、下载 WAV、刷新持久化和黑洞历史。
- `npm run test:e2e:desktop`：5 个 Electron 本地构建测试通过；验证全屏进入/退出、存档恢复、安全桥、重启持久化、黑胶实播、加载应用资源中的手势模型和 Windows 专注守护回归。正式安装包仍需由 CI 的 packaged E2E 单独证明。

自动测试不能代替三项人工确认：设备是否实际发声、真人手势是否舒服可靠，以及 Windows“另存为”对话框中选择真实路径后的文件能否被你常用的播放器打开。
