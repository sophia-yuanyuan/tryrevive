# 云端项目理解纵向链路验收

状态：`PARTIAL CURRENT`（协议、支付回调、隐私数据控制和验收门禁已实现；staging 安全闸门已部署，真实处理仍关闭）

目标：用户只看界面，不读代码；确认项目内容不会在不知情时上传，云端结果也不会直接覆盖本地项目。

## 当前可以直接验收

1. 打开桌面版，在首个入口页同时看到“项目文件夹”“说一段话或上传现有材料”“本地文字”。
2. 语音/附件入口不要求先创建一个空项目，也不要求用户填写自己的 API Key。
3. 未配置可信服务地址的安装包必须直接显示：`当前不会上传任何内容`。
4. 页面不能出现上游模型选择或 API Key 输入框。
5. 关闭云端入口后，手工填写、项目判断、下一小步和专注链路仍能正常使用。
6. 重启应用，原有项目、证据和返回计划不能丢失。

满足以上六项，只能说明“安全降级通过”，不能说明云端识别已经完成。

## 接通测试服务后验收

以下步骤需要已经部署的 staging 服务、服务端 OpenAI 凭据、审核过的模型名称和两类专用测试会话。当前 staging Worker、D1 和两类测试会话已经存在，但没有 OpenAI Secret，模型审核与真实处理开关仍关闭，因此真实远端仍属于待验收项。自动测试已经覆盖“报价 → 预留 → 上传 → 待确认摘要”；`Staging model quality review` 会用 10 份中英文合成材料生成待人工签字的模型审核报告；`Remote cloud acceptance` 再验证真实协议与退款。三者都不能替代尚未发生的生产上线。

1. 云端入口显示服务可用，但不要求填写 API Key。
2. 输入 TryRevive 算力兑换码后，界面显示剩余语音分钟和项目理解次数。
3. 选择附件或录音后，文件仍留在本机；点击“查看预计消耗”时只发送通用来源类型、大小和语音时长，不发送真实文件名或内容。
4. 上传确认页必须显示本次消耗、内容用途和保留说明，并能取消。
5. 余额不足时，“确认上传”不可用，服务端也不得收到文件内容。
6. 确认上传成功后，显示“待你确认的草稿”：最初目标、最后进度、卡点、可能原因、下一步和不确定项。
7. 点击“查看 TryRevive 的恢复判断”后，进入统一的“我猜你做到这里”页面；此时本地仍没有正式项目，只有点击“正确，继续”或修改并保存后才创建。
8. 重复点击或网络重试使用同一个幂等请求号，只能扣一次。
9. 上游失败时显示额度已归还；刷新余额后必须与失败前一致。
10. 若服务端已经完成、但客户端回包丢失或本地保存失败，重启后应使用加密保存且不含正文／原文件名的检查点找回同一草稿；仍在处理时显示等待状态，失败或过期时显示退款状态。

## 已实现但尚未完成外部接通

- Stripe Checkout 创建、服务端原始请求体签名验证、重复回调去重和支付入账已经实现；真实商户、Price、live Secret、webhook endpoint、退款规则和真实支付 E2E 尚未配置或审核。
- OpenAI 服务端适配器已经实现，并把 staging 的 `review` 与正式 `approved` 分开：review 模式只允许合成审核，客户端与 production 预检均拒绝把它当作已批准服务。仓库仍没有真实凭据或已签字审核记录，远端真实分析尚未运行。
- `tryrevive.online` 的生产预检已经实现；截至 2026-08-08，根域没有 A/AAAA，`www`、`api`、`staging-api` 均未解析，域名所有权 TXT 也未完成受保护环境核验。
- 真实语音、PDF、DOCX、余额不足、重复请求和上游失败的手动远端 E2E 已有 Windows 工作流；staging 与专用测试账户已准备，但 OpenAI Secret 和审核通过的模型仍不存在，本轮只能验证它会安全跳过或失败关闭，不能记为通过。
- TryRevive 自有隐私页面、云端数据 JSON 导出、原文不落库存储说明/删除核验、永久删除云端账户入口已经实现；运营主体、司法辖区、隐私邮箱和支付退款责任人仍需提供后才能成为正式法律政策。

## 已自动验证、但不等于已经上线

- 兑换码只保存哈希后的会话凭据，可向同一账户续充；失效凭据不会悄悄把充值转到新账户。
- 报价只保存匿名来源类型、MIME、大小和语音时长，不保存真实文件名或内容。
- D1 账本按“预留、结算、释放”记录；同一个幂等请求只预留一次。
- 云端处理请求号与通用材料类型会由 Electron `safeStorage` 加密保存；正文、附件字节和原文件名不会写入该检查点。账户本人可在门禁关闭后继续查询任务状态，另一账户得到 `not_found`。
- 新建任务短暂返回 `not_found` 时会保留检查点并允许稍后复查，不会立即生成新请求；本地状态只保留最近 50 个已交付任务号用于幂等去重，不含正文、文件名或项目内容。
- 任务仍需对账时不能退出云端账户；恢复草稿一旦安全写入本地，即使检查点清理失败，下一次恢复也不会重复创建待确认项目。
- 余额不足在内容上传前拒绝；上游失败、未上传且预留过期时完整归还额度。
- 另一账户即使猜到请求号，也不能读取已生成的项目草稿。
- staging Worker 已部署，但真实处理方、模型审核和支付开关继续默认禁用；仓库中的示例配置仍不含真实数据库 ID，也不会由普通 CI 自动部署。
- OpenAI 凭据只从 Worker 服务端 secret 读取，客户端没有 API Key 输入框；缺少启用开关、密钥或模型时处理方保持关闭。
- 录音先发送至转写接口，转写文本再进入项目分析；附件以内联文件输入发送，不创建长期 Files API 文件。
- 发送给处理方的文件名会改为通用名称，不泄露用户原始文件名；Responses 请求设置 `store: false`。
- 每次 Responses 分析请求会携带稳定的匿名 `safety_identifier`：它由随机云账号 ID 加固定用途前缀后做 SHA-256 得到；原始账号 ID、会话令牌、姓名、邮箱、项目名、文件名和材料内容都不会被用作该标识。OpenAI 可以据此关联同一匿名云账号的多次分析请求。
- 分析使用严格结构化字段；无效 JSON、空转写或上游错误不会写入项目，错误路径只记录稳定代码并归还预留额度。
- Stripe Checkout URL 只允许官方托管域名；客户端重定向、刷新余额或伪造“已支付”都不能入账，只有验签后的 webhook 可以记一笔且最多一笔。
- 云端数据导出不含会话令牌或原文；永久删除会撤销会话并删除账户、余额、账本和派生分析，本地项目不会随云端账户一起删除。
- 两个生产工作流都只允许手动触发并绑定受保护 GitHub Environment；普通 CI 不会访问生产、不消费真实算力，也不会部署。

这些项目完成前，不得收取真实款项，也不得声称 TryRevive 已经能够自动理解任意附件。即使接通，也只能承诺支持清单内、大小不超过 25 MB 的格式；模型给出的仍是待用户 Confirm/Correct 的恢复草稿。
