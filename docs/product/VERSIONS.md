# TryRevive 版本地图与回退方案

## 版本定义

### V1 — 注意力辅助版

- 建议分支：`version/v1-attention`
- 精确提交：`6105ea050d903b41fca2dac829d80836030d1d73`
- 提交日期：2026-07-07
- 产品定位：数字戒断、专注启动与注意力守护
- 已有能力：关键词直达、App Dock、限时浏览、冥想、桌宠、云朵心语与 AI 心语
- 不包含：停滞项目复活对话、Revival Brief、项目存档、行动证据与周复盘

这是仓库中最后一个完全没有“项目复活”代码的稳定提交，适合作为 V1 的可回退基线。

### V2 — 停滞项目复活版

- 建议分支：`version/v2-revival`
- 原始整合提交：`65593de75e9544e750ed188d40500f722b48a588`
- 纯项目复活提交：`c9e9582990e6425e836e39fcb4396b6384b83919`
- 提交日期：2026-07-11
- 产品定位：恢复停滞项目的上下文，并推进一个可验证的微动作
- 新增能力：复活对话、Revival Brief、5–10 分钟动作、完成证据、45 分钟短冲刺、项目存档、周复盘与数据导出
- 当前状态：注意力实现保留在历史代码中用于回退，但 V2 不再暴露注意力标签、心语浮层、公众号脚本、MBTI/桌宠注册流程或专注监控

这是当前线上版本，也是本次报名建议使用的版本。

### V3 — Revival Core 本地候选版

- 技术规格：[`PRD_V3_REVIVAL_CORE.md`](PRD_V3_REVIVAL_CORE.md)
- 产品基线：[`PRD_STUDENT_MVP.md`](PRD_STUDENT_MVP.md)
- 产品定位：面向在校大学生，在第一次复活后持续从上次成果继续
- 本地候选能力：结构化项目状态、动作与成果关联、回流、公开 GitHub 上下文、JSON 合并和日历导出
- 当前状态：本地已验证候选；尚未批准推送或部署，不能描述为当前线上能力

V3 不以 Team、Agent Router、商业套餐或 RSI 叙事作为发布门槛。是否发布只看学生 MVP 体验、事实边界和用户确认。

## 产品概念状态

| 概念 | 含义 | 当前状态 |
|---|---|---|
| Revive | 恢复现场、判断项目、确认下一小步 | 已有核心实现，体验待学生验证 |
| Loop | 执行、留下进度、安排回流、从成果继续 | 已有基础实现，V3 本地候选更完整 |
| 条件式卡点诊断 | 建议不确定或被拒绝时最多 3 问 | 规格完成，尚未实现 |
| Learn | 从获得同意的假名化反馈提出策略改动，评测后人工批准 | ADR 已定义，尚未自动化 |

## 为什么选择这两个提交

仓库检索结果：

- `6105ea0` 在 `index.html` 与 `app.js` 中没有 `Revival`、`停滞项目` 或 `项目复活`。
- `65593de` 是第一次集中加入完整项目复活流程的提交。
- 两个提交相邻，版本边界清楚，不需要猜测或依赖聊天记录。

## 推荐分支结构

```text
master
└── 当前线上版本；截止前不移动

version/v1-attention
└── 6105ea0；注意力辅助版

version/v2-revival
└── c9e9582；纯停滞项目复活版
```

不使用强制推送，不覆盖历史提交，不删除旧分支。

## 回退方法

### 临时查看 V1

```powershell
git switch version/v1-attention
```

### 回到 V2

```powershell
git switch version/v2-revival
```

### 回到当前线上主分支

```powershell
git switch master
```

切换前必须确认工作区没有未保存修改。现有 `design/prototypes/` 与 `private/submissions/` 中的报名草稿不应被纳入版本切换或公开提交。

## 截止前发布原则

1. 报名只使用 V2 的公开演示地址。
2. V1 只作为独立历史版本与产品探索证据，不在同一份报名里当作第二个主产品。
3. 若需要“纯 V2”界面，只在 `version/v2-revival` 的后续提交中隐藏注意力工具入口，不删除底层代码。
4. 任何 Pages 切换、域名修改或分支推送都必须先确认目标与回退点。
