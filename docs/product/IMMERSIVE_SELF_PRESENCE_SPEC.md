# TryRevive 唱针化身沉浸专注规格

状态：`NEW CONCEPT`，等待实现与真实用户验收

品牌：`TryRevive`

正式域名：`tryrevive.online`

## 要解决的问题

用户说“我想进入电脑里面工作”，不是想多维护一个游戏角色，而是想从旁观项目列表，切换成真正身处当前行动之中。

TryRevive 因此不做捏脸、换装、等级或虚拟宠物。用户在空间里的化身是一枚很小的发光唱针：它代表“我此刻把注意力放在哪里”。项目是唱片，下一小步是唱针唯一可以落下的位置，完成结果会成为封面拼图的一部分。

## 从参考中吸收什么

用户提供的工作台图片可转译为四个连续动作，而不是照搬它的品牌、价格或能力声明：

1. **收拢**：把语音、附件和脑中的烂尾项目放进来。
2. **找回**：需要行动时，找回原目标、最后进度和停滞位置。
3. **落针**：只把一个 5–20 分钟的最小行动放到眼前。
4. **留痕**：结果变成下次入口和独一无二的黑胶纪念。

参考互动站点的可取部分是交互语法：摄像头开关始终可见、保持手势时显示进度、键盘/鼠标/手势等价、随时重置、一次只玩一个短互动。TryRevive 不照搬玻璃材质或街机小游戏；所有互动都必须帮助用户更快开始或留下结果。

## 单一纵向链路

```text
选择一个已经生成“下一小步”的项目
  -> 点击“以唱针进入这一步”
  -> 全屏先显示上次现场
  -> 发光唱针从封套边缘移动到当前行动
  -> 用户按住鼠标/触摸/空格 0.8 秒“落针”
  -> 唱片开始缓慢转动，沿用现有计时器
  -> 空间只保留项目名、下一小步、完成标准和退出入口
  -> 用户点击“我留下了一个结果”
  -> 唱针抬起，封面拼图补上一块
  -> 进入现有成果记录页
```

保持 0.8 秒必须有可见进度环；松开即取消，不误触开始。`prefers-reduced-motion` 开启时跳过移动动画，只保留状态变化。

## 操作等价

| 意图 | 鼠标/触摸 | 键盘 | 可选摄像头手势 |
|---|---|---|---|
| 移动视线 | 拖动空间 | 方向键 | 张开手掌左右移动 |
| 选中当前行动 | 点击发光位置 | Tab / Enter | 握拳保持 |
| 落针开始 | 按住 0.8 秒 | 按住空格 0.8 秒 | 拇指向上保持 |
| 离开 | 可见“离开专注” | Esc | 不设置，避免误退出 |

摄像头始终默认关闭。不开摄像头时，完整链路仍可用鼠标、触摸和键盘完成。

## 专注空间中的“本人”

- 唱针不是人格评分，也不显示自律、连续天数或等级。
- 唱针停在哪里，只表示当前行动焦点，不表示用户好坏。
- 偏离提醒触发时，唱片减速并显示现有呼吸重置层，不使用羞辱或刺痛文案。
- 用户选择暂停或放弃项目时，唱针安全抬起；数据仍保留。
- 真实摄像头画面不映射成头像、不保存、不上传。

## 与现有功能的关系

`CURRENT`：全屏专注、上次现场、当前行动、同一个计时器、Windows 偏离守护、可退出黑幕、完成心情、黑胶收藏、本地 WAV、可选本机摄像头手势。

`NEW CONCEPT`：唱针化身、0.8 秒落针、专注中的唱片转动、完成后封面补片动画。

本规格不新增账户、支付、云端模型、WebGL 引擎或摄像头识别类别。

## 验收标准

1. 从“执行”页到计时开始不超过两个主要动作。
2. 用户在 5 秒内能读出当前唯一要做的事情和完成标准。
3. 不使用摄像头也能完成全部链路；拒绝摄像头权限后不出现死路。
4. 鼠标、触摸、键盘都能落针、留下结果和退出。
5. 动画不新建第二套计时状态；刷新、退出再进入时仍读取同一项目行动时间。
6. `Esc` 和可见退出按钮始终有效；全屏不是 kiosk。
7. 完成动画结束后进入真实成果记录，不把动画播放当作项目完成证据。
8. 如果三名测试者中有两名因为场景找不到“开始这一步”，立即退回现有简洁专注界面，不继续增加装饰。
