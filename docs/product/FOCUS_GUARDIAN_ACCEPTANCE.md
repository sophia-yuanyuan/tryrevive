# Windows 专注守护纵向验收

状态：`PARTIAL CURRENT`

这条链路只判断“是否离开本次允许的软件”，不能判断用户在同一个浏览器或同一个软件里是否正在做最小行动。它不使用羞辱文案，也不能替代用户对目标和环境的调整。

## 用户直接验收

1. 打开一个已经进入“执行”的项目，点击“进入全屏专注”。
2. 在专注页看到“Windows 偏离提醒 · 默认关闭”；未点击开启前，不应启动系统监测。
3. 默认选择“严格白名单 · 立即拉回”，再从文档、沟通、开发、浏览器与设计分组一键选择本次需要的软件，例如 WPS、飞书、Chrome 或 VS Code；找不到时可以展开输入其他软件名。严格模式没有选中任何软件时不能启动，避免把名单配成空集；快捷项与手写项合计最多 32 个进程别名。
4. 点击“开启本次白／黑名单守护”，状态变为“运行中”。界面明确写明：只读取前台应用名和系统空闲时长，不读取按键、窗口标题或网页。
5. 切换到未允许的软件。严格白名单模式应立即让 TryRevive 重新全屏显示黑幕；如果本人主动改选“12 秒宽限 · 可短暂切换”，才在持续偏离 12 秒后拉回。两种模式都不终止或卸载其他软件。
6. 黑幕必须同时提供：
   - `Esc · 离开专注`；
   - “这是必要工作”：将刚才的软件只加入本次允许列表，并最小化 TryRevive；
   - “我回到这一步”：重新开始偏离计时；
   - “结束本次守护”。
7. 90 秒没有键盘或鼠标活动时，偏离计时暂停，不弹黑幕。
8. 关闭专注、刷新页面、关闭应用、渲染进程异常退出或重启应用后，守护必须停止，不可后台自动恢复。刷新后重新进入专注时，必须由本人再次选择名单并主动开启。

## 自动验证

- 单元测试验证应用名标准化、严格白名单立即拉回、可选 12 秒宽限、返回允许软件和空闲暂停。
- Windows 集成测试直接调用只读监测脚本，验证它只输出一个进程名。
- Electron E2E 启动一个测试自己创建的空白记事本，真实切换 Windows 前台后验证 TryRevive 收到 Notepad 偏离事件、重新成为前台、能主动停止守护，并验证再次运行中刷新页面后主进程监测已经停止。测试只关闭本次新建的记事本进程，不碰用户原有窗口。
- Windows 打包必须包含 `foreground-monitor.ps1`，并继续通过安装版、便携版和打包后 Electron E2E。

当前自动化已覆盖 Windows 记事本这一种真实跨软件拉回。Chrome、Word、VS Code、多显示器、系统权限提示和不同 Windows 缩放比例仍是安装包人工兼容性验收项，不能从单一记事本用例推断为全部通过。

## 当前边界

- `CURRENT`：Windows 前台进程名、系统空闲时长、会话白名单/黑名单、默认严格白名单立即拉回、可选 12 秒宽限、必要工作临时放行、可退出黑幕。
- `NOT IMPLEMENTED`：识别同一个浏览器里的具体网站、识别同一个软件里的实际工作内容、读取按键内容、后台永久封锁、摄像头判断注意力。
- “严格白名单”表示检测到名单外软件后立即把 TryRevive 拉回，不表示阻止 Windows 启动、强制结束或卸载软件。浏览器一旦被允许，本次守护不能区分工作网页和娱乐网页。以后若需要网站级白名单，应使用单独、显式授权的浏览器扩展，不应靠读取键盘或偷偷截屏实现。
