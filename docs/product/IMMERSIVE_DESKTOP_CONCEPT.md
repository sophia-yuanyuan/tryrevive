# TryRevive 沉浸式桌面体验概念

状态：`PARTIAL CURRENT`，已有多条可运行纵向切片，尚未经过真实用户验证

基线：`codex/frontend-platform@4967c4e`

品牌与域名：产品统一使用 `TryRevive`，正式域名为 `tryrevive.online`。

## 用户结果

用户第一次打开桌面应用时，可以先把脑中所有未完成的项目放进本机，再选择一个项目找回目标、停滞原因与下一小步，并进入一个自愿、可退出的全屏专注空间。项目完成后，应用用逐渐清晰的黑胶封套和一段本地生成的短音型留下纪念；项目放弃时使用弯折唱片的中性视觉，不制造失败感。

## 本轮实现

- Electron 默认全屏启动，但不使用 kiosk，用户仍可退出全屏或关闭应用。
- 首屏支持多行批量收纳、本地文本文件导入和浏览器原生语音转写入口。
- 语音转写不可用或权限被拒绝时明确降级到文字输入，不声称已完成 AI 识别。
- 复用现有项目状态、恢复问题、决策、下一小步、证据和回流数据。
- 将历史 `c6a4734` 的“上次现场 → 现在只做这一步 → 全屏计时”迁移到 Vue。
- 云端理解入口不要求用户填写 API Key；桌面端只连接 TryRevive 自有服务地址，并在每次上传前显示价格、范围、保留期和主动同意。当前仓库保留后端额度与可替换模型适配层，尚未接入真实账户、支付和模型供应商。
- Windows 偏离提醒默认关闭，必须由用户主动开启；只读取前台进程名与系统空闲秒数，不读取按键内容、窗口标题或网页。持续偏离 12 秒后回到可退出的全屏重置层。
- 完成项目展示可交互黑胶封套；用户选择完成心情后，根据每一步实际时长、项目记录和心情在本机生成同一首 48–96 秒 PCM WAV，可播放和导出。
- 黑胶星球使用 CSS 透视和三维变换呈现完成唱片与黑洞历史，支持鼠标拖动、触摸滑动、方向键和唱片按钮；放弃项目保留为中性历史记录。
- 摄像头手势默认关闭，用户阅读说明并主动开启后才加载随应用打包的 MediaPipe 模型；画面在本机逐帧处理，不保存、不写入项目。张开手掌、握拳和拇指向上分别提供转动、选择和打开入口，鼠标、触摸和键盘始终可完成同样操作。
- “用户本人进入项目”的下一条纵向链路采用发光唱针化身，不做捏脸或等级系统；详见 `IMMERSIVE_SELF_PRESENCE_SPEC.md`。

## 尚未实现

- 自动理解任意语音或附件中的完整项目上下文；当前只有显式上传、报价、同意和结构化草稿边界。
- 可供真实用户使用的云端账户、充值/支付、语音识别、LLM 停滞原因分析和自动建议服务。
- WebGL 或写实物理级黑胶星球；当前实现是轻量 CSS 3D 纵向切片。
- 生成式音乐模型与多轨编曲导出；当前实现是确定性的本地规则合成 PCM WAV，不消耗云端算力。
- 唱针化身、保持落针、专注中唱片转动和完成后封面补片；当前仍使用简洁的三阶段全屏专注界面。

以上尚未实现能力仍需要单独的隐私、权限、后端、成本和可用性设计，不能由当前纵向切片代替。

## 安全边界

- 不把注意力偏离解释为人格、自律或价值失败。
- 不使用“醒悟”“沉迷”“你未来会成为什么人”等强迫性文案。
- 不在用户未同意时监测其他应用、摄像头、麦克风或窗口活动。
- 全屏是环境切换，不是惩罚；`Esc` 和可见按钮始终可以离开专注层。
- 放弃项目是有效决策，不影响历史记录和数据导出。

## 验收

1. 桌面窗口首次显示时为全屏，现有安全 preload 与外部链接限制不回退。
2. 用户可一次创建多个项目；重复项被去重，空行不创建项目。
3. 本地文本导入只读取用户主动选择的文件，限制大小并保留文字兜底。
4. 专注层显示上次现场、当前动作、完成标准和同一个计时器，且随时可退出。
5. 完成与放弃得到不同的黑胶视觉；声音必须由用户主动播放和停止。
6. 支持 `prefers-reduced-motion`，主要交互可用键盘完成。
7. 完成项目后必须先选择当时心情；刷新后选择、唱片与收藏位置仍保留。
8. 播放与导出使用同一份本地 WAV；桌面版导出前显示系统“另存为”，网页版触发浏览器下载。
9. 黑胶星球可用鼠标、触摸和方向键转动；完成项目与放弃项目都可从列表或场景重新打开。
10. 摄像头默认关闭；主动开启后本地模型可加载、预览持续可见，关闭或离开页面后立即释放视频轨道；权限被拒绝时仍可使用鼠标、触摸和键盘。
