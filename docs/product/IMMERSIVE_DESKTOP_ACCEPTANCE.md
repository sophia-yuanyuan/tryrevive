# TryRevive 沉浸式桌面纵向链路验收

适用版本：`codex/frontend-platform@7959f1a`

目标：不检查代码，只判断一个真实停滞项目能否从“脑内负担”走到“留下真实进度与黑胶纪念”。

## 验收前准备

准备三个真实但不敏感的项目名称，例如：

1. 申请一个黑客松；
2. 报名一项考试；
3. 完成一个停滞的作品集页面。

再为其中一个项目准备：上次做到哪里、具体卡点、最近节点、为什么仍值得继续。

## 一条完整链路

### 1. 启动与收纳

- 双击启动 TryRevive。
- 预期：应用直接进入全屏，但仍能正常退出或关闭，不是锁屏。
- 在“所有还在心里的项目”中每行输入一个项目。
- 点击“收下这 3 个项目”。
- 预期：设置中的本地项目列表同时出现三个项目，没有重复或丢失。

### 2. 语音入口

- 点击“用语音说”，说出一个项目，再停止倾听。
- 预期：支持时出现可编辑文字；不支持或拒绝权限时明确显示降级提示，已经输入的内容不丢失。
- 当前版本不通过标准：界面声称识别成功，但没有显示真实文字。

### 3. 找回现场

- 选择一个项目，填写上次进度、卡点、截止节点和继续理由。
- 选择“继续”“缩小”“求助”“暂停”或“放弃”。
- 预期：暂停和放弃是平等选项，不出现羞辱或强迫复活文案。

### 4. 下一小步

- 检查系统给出的动作、完成标准和时间盒。
- 把动作修改成你真正接受的版本，再确认。
- 通过标准：动作能在 5–20 分钟产生一个可见结果；不是“继续努力”“再研究一下”等空动作。

### 5. 全屏专注

- 点击“直接进入全屏专注”。
- 预期依次看到：上次现场 → 当前只做这一步 → 计时与完成标准。
- 点击“我偏离了，帮我回来”，再点击“我回到这一步”。
- 预期：出现呼吸和你自己填写的继续理由；不出现人格攻击、自律评判或不可关闭黑幕。
- 按 `Esc`，预期随时离开且进度不丢失；再次进入后继续同一动作。

### 6. 成果、回流与黑胶

- 点击“我留下了一个结果”，填写本次实际成果。
- 安排 3–7 天后的回流入口并刷新/重启应用。
- 预期：重启后直接看到上次成果和继续入口，无需重述全部背景。
- 将项目标记为完成，点击黑胶封套并播放项目短音型。
- 预期：唱片能从封套中取出，声音只能由用户主动播放和停止。
- 对另一个项目选择放弃，预期显示弯折唱片且历史仍保留。

## 验收结论

只有下面六项全部为“是”，当前纵向链路才算通过：

| 问题 | 是 / 否 |
|---|---|
| 我能一次放下多个未完成项目吗？ | |
| 我能在三分钟内说清一个项目的现场吗？ | |
| 下一小步是我真正接受且能产生可见结果的吗？ | |
| 专注界面帮助我开始，而不是惩罚我吗？ | |
| 重启后我能从上次成果继续吗？ | |
| 黑胶反馈与真实项目完成状态一致吗？ | |

若任一项为“否”，记录：所在页面、刚才点击的按钮、期望、实际结果；不需要描述代码原因。
