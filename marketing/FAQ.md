# TryRevive 常见问题

状态：对外回答草案

## TryRevive 是什么？

TryRevive 是一个面向在校大学生的项目复活工具。它帮助学生恢复课程、竞赛、作品集或科研项目的上下文，把下一步约束成一个带时间盒和完成标准的动作，并在完成后保存证据和下一次入口。

## 初始用户是谁？

首发阶段只聚焦高校在读学生，特别是拥有真实停滞项目、并在未来 90 天内面对提交、答辩、展示、比赛或申请节点的学生。非学生个人创作者和职场用户不是前三个月的主动获客对象。

## “三个月获取 1,000 名大学生用户”如何计算？

默认按正式增长启动后的连续 90 天计算。一名激活学生需要自主确认在读身份、带入至少一个真实停滞项目、完成首次恢复现场、接受或修改出一个下一小步，并在 24 小时内实际开始。访问页面、关注账号或只加入群聊不计入。同一假名化标识只计一次；由于本地环境无法可靠排除清缓存和多设备重复，对外应写“估算独立激活学生”，不能声称 1,000 个已验证独立自然人。1,000 人是增长目标，不是当前成绩；7 天实质成果和 30 天再次推进另行衡量产品质量。

## 创业者也是目标用户吗？

前三个月不是。创业者可以参与访谈、提供同行反馈、连接校园资源或转介绍真实学生项目，但非学生创业者不计入 1,000 名目标，也不能替代学生行为证据。仍在校的学生创业者按学生标准判断。

## Loop 是产品的第二个环节吗？

在用户生命周期层面是：第一次的 Revive 负责找回现场、判断项目并确认下一小步；之后的 Loop 负责执行、留下进度、安排回流和从上次成果继续。但 Loop 不是第二个页面，学生端只会看到“下一轮”或“从上次继续”等自然语言。

## 产品会加入 GrillMe 或 RSI Agent 吗？

当前只把它们作为产品设计启发。学生端计划验证一个可跳过、最多 3 问的“帮我问清楚”，不是攻击性访谈，也尚未上线。内部产品学习会采用评测、人工批准和可回滚的门槛，不允许系统直接修改线上规则或代码。对外不能宣传为已经实现的 RSI 能力。

## 它和待办清单有什么不同？

待办清单通常从“我已经知道要做什么”开始。TryRevive 服务于更早的时刻：用户只记得模糊目标，或者知道项目重要，却不知道上次做到哪里和此刻该做什么。

## 它和 ChatGPT、Claude 或 Codex 有什么不同？

这些工具擅长生成内容或执行具体能力。TryRevive 更关注执行治理：此刻只做哪一个动作、为什么做、什么算完成、是否需要授权，以及完成后如何继续。它也可以为人或 Agent 提供同一个 Action Contract。

## 必须使用 AI 吗？

不必须。核心项目复活流程由结构化问题和本地规则支持。AI 可以用于辅助心语或知识问答，但服务不可用时不应阻断恢复、行动、证据和回流闭环。

## 我的数据存在哪里？

当前数据默认保存在使用产品的浏览器中，用户可以主动导出 JSON。当前版本不应被当作跨设备备份或正式云存储服务。

## TryRevive 会自动修改我的文件或代码吗？

默认不会。任何写文件、提交代码、发消息或修改外部系统的动作都应另行获得用户授权。

## 它能读取 GitHub 项目吗？

V3 本地候选版已经实现公开 GitHub 仓库上下文和部分 commit/PR 证据判断，但该版本尚未批准上线。当前不能宣传私有仓库连接。

## 什么是“完成证据”？

完成证据是能说明动作结果的内容，例如一段文字、文件名、公开链接或 commit。TryRevive 的设计原则是不把用户自述自动包装成系统验证；证据的可信等级应与实际来源一致。

## TryRevive 适合团队使用吗？

当前重点仍是个人项目恢复。团队证据治理和权限能力属于未来探索方向，尚不能作为成熟功能销售。

## 它能治疗拖延症或注意力障碍吗？

不能这样描述。TryRevive 是生产力工具，不提供医疗诊断、治疗或心理健康功效保证。

## 目前是否收费？

当前文档没有已确认的正式定价。商业化方向仍在探索，不应承诺具体价格、套餐或上线时间。

## 我怎样参与测试？

在校大学生可以带一个真实、已经停滞一段时间的课程、竞赛、作品集或科研项目，完成一次“恢复现场—单步行动—留下证据—安排回流”的完整流程，并反馈哪一步最有帮助、哪一步造成了新的摩擦。
