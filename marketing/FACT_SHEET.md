## 首发增长目标

- 目标人群：高校在读学生；
- 目标周期：从正式增长启动日起连续 90 天；
- 目标数量：1,000 名估算独立激活大学生用户；
- 默认口径：学生自主确认在读身份，带入真实停滞项目，完成首次恢复现场，接受或修改出一个下一小步，并在 24 小时内实际开始；同一假名化标识只计一次；
- 当前状态：增长目标，尚未达成，也没有可对外发布的用户规模数据。

正式启动前必须准备获得用户同意的假名化统计或等价测量方案。页面访问量、社交关注量、入群人数和当前浏览器中的本地账号数不能直接当作 1,000 名激活用户。当前无账号环境无法可靠排除清缓存、多浏览器和多设备重复，因此不能声称这些是 1,000 个已验证独立自然人。

## 可以由当前仓库支持的表述

- TryRevive 面向停滞项目恢复与执行场景。
- TryRevive 的首发 Marketing 人群聚焦在校大学生，优先场景是课程、竞赛、作品集和科研项目。
- 产品通过结构化问题恢复上下文，并生成带完成标准的微动作。
- 当前代码包含项目列表、暂停与恢复、行动证据、周复盘和 JSON 导出。
- 核心项目复活流程可以在远程 AI 不可用时继续运行。
- 仓库包含 Chrome Extension 原型、Worker 代码和公众号知识库实验。
- V3 本地候选版具有 ProjectState v2、Action Contract、证据分级、Return Plan 和公开 GitHub 上下文能力。
- 当前 V3 单元测试和本地 Chrome 端到端测试已经通过。

## 只能作为目标或待验证假设的表述

- 提高项目开始率、完成率或次日回流率。
- 减少恢复项目所需时间。
- 用户更愿意留下完成证据。
- 团队会为证据治理或项目恢复付费。
- 注意力守护能够减少内容平台中的无目的浏览。
- 条件式卡点诊断能够提高建议质量。
- 基于反馈的产品学习能够提高自评有意义复活率。

以上内容可以写成“希望验证”“设计目标”或指标定义，不能写成已经证明的产品效果。

## 当前不能承诺

- 成熟的团队权限、审计和企业管理；
- 自动修改外部文件、自动提交代码或自动发送消息；
- 私有 GitHub 仓库连接；
- 所有浏览器和移动设备兼容；
- 商业化价格、Pro/Team 上线时间；

## 数据与隐私事实

- 项目与偏好数据默认保存在当前浏览器。
- 用户可以主动导出 JSON 数据。
- 核心流程默认不会修改外部文件。
- 公众号实验只处理用户主动提供的公开链接或正文，不绕过登录、验证码或平台限制。
- Worker Secret 不应出现在前端代码、Marketing 文档或截图中。

## 指标定义，不是当前成绩

- 估算独立激活学生数：自述在读、带入真实停滞项目、完成恢复、接受或修改出下一小步，并在 24 小时内开始动作；按假名化标识去重的人数。
- 三分钟可接受动作率：从开始恢复到接受或修改出下一小步不超过三分钟的项目比例。
- 7 天实质成果率：7 天内产生学生本人认定为实质推进成果的项目比例。
- 30 天继续率：30 天内再次实质推进同一项目的比例。
- 自评有意义复活率：所有开始 Revive 的合格项目中，同时满足“绑定成果记录 + 中性自评为实质推进”的 7 天成果和 30 天再次推进的项目比例。
- 无需重新解释的恢复率：回流时不需要重述全部背景即可继续的项目比例。

来源验证只能说明成果来源与时间关联，不能证明成果质量或目标已经完成。

任何对外数据必须同时说明统计周期、样本量、用户范围和计算方法。
